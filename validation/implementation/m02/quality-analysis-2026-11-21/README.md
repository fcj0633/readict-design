# M02 COL 词典质量归因与测试验证报告

日期：2026-11-21（Asia/Shanghai）。范围：用户批准的质量分析计划；**分析已完成，M02 正式开发仍部分完成**。本轮没有修改正式提取规则、数据契约、迁移、Provider或前端，没有操作数据库，没有批准修正／排除任何源记录。

## 1. 结论与建议

**当前应优先修复 COL 专用提取和分类逻辑，建议保留现有 COL 继续开发。没有证据支持把56,202条失败全部当作词典损坏，也没有必要仅因该数量更换解析器或整本词典。** 独立实现对完整源文件的读取一致；当前失败的主要表征是提取器无法识别已经存在的双语文字、子词条或交叉引用。

词典内容确实有局部缺口：13条记录正文为空／None、268个源位置的英文词形说明目标空缺，以及根引用子集中7个直接自环和1个缺目标的引用。另有派生词段只提供词形／词性，没有独立释义；这是本地源内容能力与应用逐义中文要求的差异，不能一概断言为文件损坏或导出丢失。

现有成功结果也不等于字段完整：随机100条成功记录中，55条丢失用法或补充词性标签；定向审查还发现关系文字混入zh字段。改进后应同时检查遗漏、错误提取和不确定项，不能仅看失败数下降。

是否需要更完整版本：**可作为局部缺陷的补充对照材料，但不是修复当前技术问题的前置条件。** 本次未拿其他词典补词、未在线翻译、未猜写释义。

### 2.1 两条读取路径

- 路径A：当前js-mdict6.0.6适配器，保留物理索引顺序和重复key，严格UTF-8解码。
- 路径B：隔离Python3.10.8环境，读取未修改的[readmdict实现](https://github.com/ffreemt/readmdict/blob/d9c53dc1515f99ae5a2d6b1d89212c9b680e0c59/readmdict/readmdict.py)，固定提交`d9c53dc1515f99ae5a2d6b1d89212c9b680e0c59`，关闭样式替换，保留库实际输出。按源位置配对，同时按key＋正文摘要的多重集合验证，未用对象覆盖重复key。
- 参考包入口强制要求LZO，但实现子模块支持可选LZO。本次直接加载原实现子模块及原相对依赖，未修改解码算法；实际MDX5077块、MDD1块全部为zlib，无需LZO，也未向应用增加Python依赖。

| 比较项 | MDX | MDD |
|---|---:|---:|
| 实际记录数 | 121872 | 2 |
| 同序号key一致 | 121872 | 2 |
| 同序号偏移一致 | 121872 | 2 |
| 原始API输出正文摘要相同 | 0 | 2 |
| 仅处理已解释的两端NUL后相同 | 121872 | 2 |
| 受控多重集合相同 | 是 | 是 |

MDX每条记录的差异都恰为：Node保留一个尾部NUL，readmdict API通过strip去掉该NUL。没有为获得一致而更改换行、去BOM、合并空白、规范化Unicode或清洗HTML。readmdict内部使用ignore解码，故同时要求Node全源严格解码成功；本次未发现非法UTF-8。参考实现的校验和断言开启且全源运行通过。原始差异数量和受控比较分别记录在[解析器比较](parser-comparison.json)，没有声称原始输出逐字节一致。

这证明本次两个读取路径对同一本地源得到相同内容；它不证明出版社原版内容、译文正确性或授权状况。

## 3. 已证实的技术问题与范围问题

### 3.1 用句末标点替代结构理解

r2主要接受显式中文节点、纯中文内容，或“英文句号后开始中文”的版式。实际COL大量使用无句号的英文短语释义。`saw`中有现成中文“格言”，但英文短语不以句号结尾，整个源记录被拒绝。类似问题在随机失败样本中大量出现。

另有“括注后含英文词形”“缩写标签后有中文”“段内箭头引用”等分支。先compact再依赖少数正则，无法完整解释这些版式。增加DOM解析器不会自动解决语义分段；应保留节点顺序、空白、括号／引号、链接及源位置，再做COL专用分段。无充分证据的段仍应保持未确定，不能简单截取第一个汉字之后的全部文本。

### 3.2 把主词头套在所有段落上

全源机器审计识别4655个带中文的嵌入子词条段，涉及3342个源位置、1650种表面词形，其中1216种没有同名精确索引。当前实现没有处理这一层身份。

`quickly`实际出现在quick词条的3个段落，`beautifully`出现在beautiful的2个段落。r2把前置子词形与中文合并后无法提取；若只强行去掉前面的英文，又会把子词条释义归到quick／beautiful，造成身份错误。本次隔离试验保留子词形、词性、释义、主词头来源和位置，5个固定段的字段与执行代理核对值全部一致，但未生成正式词条或收藏身份。

“quickly没有精确索引”因此不能作为缺词结论。需要主词条索引与子词条索引共同描述覆盖范围。

### 3.3 引用和变体未分类

726条SENSE_MISSING记录经机器审计：709条有see／same-as类根引用，另2条有带原始链接的another-spelling引用，合计711条根引用候选。余15条含空区域／仅词头元信息；其中4条在其他区域仍有正文，不能说整条完全没内容。

根引用候选中68条指向多词目标，属于本轮单词查询范围的处理问题，不是词典损坏。引用存在只证明有关系，目标义项是否可发布仍需单独验证。

优先读取原始entry://目标非常重要：本轮最初的文本试验把ibid.末尾句点剥掉，产生假悬空；原始href明确为`entry://ibid.`，该目标确实存在。该临时诊断假问题已经排除，未改正式代码。最终结果见[引用复核](reference-findings.json)。

collins-intro中的AM／also变体信息也不应丢失。它们可为部分错误引用提供反向候选证据，但不能自动覆盖源链接。

### 3.4 成功结果丢标签、混入引用

随机100条ENTRY记录中，55条丢失85项用法／补充词性标签，包括英美地区、正式程度、语法搭配和次级POS。原因可直接定位：r2过滤.additional节点后没有另存这些字段。Node纯字段断言确认基线保留0／85，诊断候选保留85／85。这是标签保留指标，不是整本词典释义准确率。

另对全源10条“zh含较多拉丁词”的风险记录逐条核对：3条把see-also关系列表混进了zh（-faced、sighted、-worthy），7条是必要的嵌入英文或用法，不能直接删除。该10条属于定向风险集，不能把3／10外推为全部成功结果的误提取率，见[风险复核](accepted-risk-review.csv)。

### 3.5 源词头、查询键与范围混用

486条词头拒绝分为：144条含内部标点，331条实际词头为多词内容，10条含相邻撇号／连字符，1条为R&B一类符号组合。331条和部分标点词需要产品范围分类；babies'-breath等10条暴露了当前语法覆盖不足，不能算源数据损坏。位置清单见[词头审计](unsupported-headwords.csv)。

还发现成功样本含-taker等词缀词头。现有查询规范会剥去两端非词字符，若直接用于源词头，将-taker与普通taker混成同一个lemma键。应先区分词缀、普通词、缩写等来源类型，再决定比较键与范围；本次没有扩展查询语法或调整正式归并规则。

25,477条跳过记录中，515条的实际词头含单词形式；检查发现这些单词形式都另有精确索引。随机100条跳过记录中有4条属于这类形式差异，其余为多词目标；本次未证明这些跳过导致独占的单词正文丢失。该结论不等于全部跳过规则已获批准。

## 4. 已定位的源内容问题及可恢复性

### 4.1 13条空正文

双读取路径确认：12条正文是None，1条NCCL正文为空。12条None共用同一种正文摘要，13个位置总共2种正文摘要。完整名单见[空记录清单](empty-records.csv)，包括moved、mutt、muzz、mv、NAIRU、NCCL、neckwear、nigh、nitramine、Num.、observant、offshoring、tabulated。

这是输入内容缺口；不能靠DOM规则生成释义。某些屈折词形可能从其他完整词条的明确词形表恢复查询关系，但不能据此抹掉该位置的源缺陷。

### 4.2 268个位置的英文关系目标缺字

272个缺口分布在268个位置，原始HTML对应段没有可补足目标的链接。children的英文复数说明目标为空；mice、went分别在中文括注保留mouse、go。经过中文关系模板和同词典词形表审计，再补核strove中的“(strive)的一种过去式”，268个位置都有同源候选依据：245个只有一个候选，23个仍有多个候选。

这些是**候选**，不是已批准修复。反向词形表不能靠排序压掉其他lemma；原文、候选证据及原始错误都应保留。strove同时说明诊断模板本身会漏分支，最初模板没有覆盖“一种”。逐位置列表见[缺目标复核](source-gap-review.csv)。

268不是源文缺陷的完整上界：例如a/c还有“abbreviation for .”类缺目标，而原r2探针仅覆盖特定of关系。报告未把未审计的全源其他缺口标为已确认。

### 4.3 根引用子集中的自环和悬空

在711条已识别根引用中，7个直接自环根为anesthetic、appall、disorient、diss、fulfill、skeptic、tidbit；包含其屈折位置后11条记录受到影响。原始链接href与显示目标均指向自身，排除了只因文本清洗而产生循环的可能。该根引用图未发现超过8跳的链；这不是全词典所有关系均已穷尽。

anaesthetic、appal、disorientate、fulfil、sceptic、titbit的AM／also信息，为其中6个自环根提供同源变体候选；diss未在本次得到相应明确替代证据。均未自动纠正。

skillful原始链接指向skilful，后者在本次全源精确key、词头和已识别的带中文子词条索引中均未找到，保留为本地词典范围内的悬空引用。没有用同义词或网络释义填补。

### 4.4 派生词没有独立释义：内容能力限制

另外审计到1006个子词条段只提供词形／词性，移除明确标签后无独立正文，涉及971个源位置、447种表面词形；按主词头／区域／段落去重为464个单位。例如irreparable中的irreparably只有ADV及用法标签。

确认这些段的.additional中也没有被误删的非括号中文释义。这一结果说明本地数据没有提供该段的独立释义；无法由本次读取对照判断是原书编辑安排还是生成MDX时省略，**不能直接称为损坏**。它同时说明提取器不能把所有collinsMajorTrans都当成必须有中文的独立义项。

447种词形中78种有精确索引位置，1种有同名根词头，未找到在别处带中文的同名子词条；369种在这三类字面位置检查中没有其他候选。位置存在不等于该处已有正确中文。见[派生词覆盖](untranslated-subentry-coverage.json)。后续应标记DERIVATION_NOTE／未提供独立释义，保留主词条有效内容和覆盖缺口；不能给派生词猜译，或默认把其lemma归到主词。

以上问题集合可能重叠，未相加制造“词典损坏率”。

## 5. 样本、实验和测试结果

### 5.1 抽样与审核口径

按`SHA256(mdxSha256 + 十进制sourceOrdinal)`升序，各取100条边界失败、100条成功、100条跳过记录。每类前70用于规则分析、后30保留验证；共210／90，序号、分组和结果见[300条样本](sample-review.csv)。固定50词外增加7个回归词，见[57词清单](fixed-regressions.csv)，没有换掉失败词。

本轮300条进行了机器结构审计和执行代理对词头、前两个关键片段、元数据机制的核对；**不是300条所有义项逐条人工金标准**。完整语义准确率和F1没有被测得，报告标为未估计。人员审批数仍为0，执行代理核对在附件中明确标注Codex，不冒充用户人工审核。

### 5.2 三组对照结果

| 指标 | 原r2／基线 | 隔离结构／关系试验 |
|---|---|---|
| 全源读取 | js-mdict路径 | Python独立路径；控制NUL后121872／121872一致 |
| 100条失败样本整条在结构上可解释 | r2均失败 | 12条；88条仍有未确定段，合计94段 |

结构感知试验仅验证明确分隔／子词条／引用路径，没有解决主量的非句式双语分段。不能据12条结构覆盖宣布质量恢复，更不能承诺99%自动修复。误提取、字段遗漏、未确定分别报告，所有候选仍为diagnostic-only。

### 5.3 已执行检查

- 现有Node测试31／31通过，确认正式工具行为未被改变。
- 隔离实验15／15通过，覆盖子词条身份、标签／括注／英文词形保留、缺目标不补写、多目标不合并、循环、悬空、8跳边界、原始链接保留句点、URL单次解码、短语边界和远程链接拒绝。

- 固定5个子段字段断言、100条成功记录的85项标签保留断言全部通过；它们独立计数，不混作新增正式测试数量。
- 两轮结构审计的summary、sample-manifest及selected-evidence摘要完全一致，见[完整性附件](integrity.json)。正式源码、锁文件、旧r2产物和源文件摘要结束时均未变化。
- 未执行Java／前端回归或数据库测试，本轮没有修改这些部分，也没有引用M01历史成绩代替本次验证。

## 6. 开源技术路径与修复优先级

参考版本、文件摘要和链接见[开源出处](open-source-references.json)。
