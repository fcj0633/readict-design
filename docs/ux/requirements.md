你现在担任资深产品设计师、UI/UX 设计师和前端工程师。

## 一、项目背景

项目是一款面向英语原版书阅读者的 Web 产品。

核心功能包括：
- EPUB 导入和书架管理
- 单页分页阅读
- 点击英文单词弹出浮动词典卡片
- 根据当前句子的词性优先展示词典释义
- 原文例句展示与主动异步翻译
- 单词收藏
- 学习库
- 单词复习
- 用户登录与个人设置

请首先阅读仓库内的 PRD、现有前端代码、技术栈和相关设计文档。

我会提供一张微读的词典浮动卡片截图作为参考。

## 二、工具使用要求

1. 检查当前环境是否提供 Frontend Design、Playwright、Figma 或其他 UI 设计相关 Skills。
2. 优先使用可用的专业设计 Skill 规划视觉和交互。
3. 如果项目尚未确定前端技术栈，优先评估 React + TypeScript + Tailwind CSS + shadcn/ui。
4. 优先复用项目现有组件和依赖，不要随意重建技术栈。
5. 使用真实浏览器进行页面验证，优先使用可用的 Playwright 工具。
6. 对每个重要页面进行截图，并根据截图进行视觉优化。
7. 如果工具缺失，明确说明缺失情况，不要假装已经完成浏览器测试。

## 三、设计风格

整体风格：Editorial 文学杂志风格。

设计关键词：
- 简洁
- 舒适
- 克制
- 专注阅读
- 暖白色
- 米色
- 深灰文字
- 适当留白
- 轻量阴影
- 清晰的信息层级

避免：
- 传统后台管理系统风格
- 大量彩色卡片
- 复杂渐变
- 过度圆角
- 大面积工具栏
- 不必要的装饰元素
- 阅读页面上过多的常驻学习组件

## 五、阅读器要求

参考微读的整体布局。

- 页面顶部展示书名和必要导航。
- 中间为单页阅读内容。
- 正文有最大宽度限制，不铺满整个屏幕。
- 右侧为简洁的垂直功能栏。
- 章节信息和页码位于阅读区域内部。
- 阅读样式支持字体、字号、行间距和背景设置。
- 保持阅读区域稳定，不能因为打开词典而改变分页。

## 六、浮动词典卡片要求

参考我提供的截图。

点击英文单词时：
- 在单词附近弹出卡片。
- 根据可视空间自动调整卡片位置。
- 卡片不得超出浏览器窗口。
- 原文单词高亮。
- 卡片不改变正文布局。

卡片包含：
- 单词原型
- 原文词形
- 音标
- 发音按钮
- 词性
- 主要释义
- 折叠的其他释义
- 原文例句
- 例句翻译按钮
- 收藏按钮
- 关闭按钮

根据当前句子词性优先展示释义，其他释义折叠。

默认只展示英文原文。

点击翻译例句后，模拟异步加载，显示中文翻译。

点击收藏后，更新收藏状态。

不要直接照搬截图中的所有尺寸和留白，而是提取其布局优点，设计更紧凑、更适合实际阅读的卡片。

## 七、交互要求

所有主要功能必须能够真实交互。

第一阶段允许使用 Mock 数据，但不能只有静态页面。

至少实现：
- 点击不同单词，更新词典内容
- 浮动卡片自动定位
- 点击空白关闭卡片
- Escape 关闭卡片
- 切换章节
- 上一页和下一页
- 修改阅读设置
- 展开其他词义
- 异步翻译加载状态
- 收藏与取消收藏
- 学习库查看
- 模拟单词复习

Mock 数据应集中管理，便于后续替换为真实 API。

## 八、实施方式

不要直接一次性开发全部页面。

首先完成以下工作：

1. 分析现有项目结构和技术栈。
2. 提取 PRD 中与 UI 有关的需求。
3. 制定页面信息架构。
4. 定义统一视觉规范。
5. 列出关键交互状态。
6. 设计阅读器和浮动词典卡片。
7. 实现可运行的第一阶段原型。
8. 使用浏览器截图检查实际效果。
9. 修复明显的布局和交互问题。

在开始大量开发前，先输出设计方案与组件划分。

请至少检查以下场景：

- 1366×768 桌面页面

最后输出：
- 已完成的页面
- 使用的工具和组件
- 实际运行和验证情况
- 截图位置
- 已知问题
- 下一阶段建议

当前目标是高质量、可交互的 UI 原型，不是完整后端系统。不要在这一阶段实现真实数据库、认证服务或 AI 翻译接口。
