# ADR-0005：独立发音库与离线 MP3 播放

日期：2026-11-22。状态：**已采纳工程方案，正式实现与验收尚未完成**。

依据：用户确认完整发音链路范围并要求新增任务不扩张已完成任务；[样本音频技术验证](../../../validation/technical/audio/2026-11-21/README.md)；[A02 独立执行文档](../implementation/A02-本地发音库处理与播放接入执行文档.md)。

## 背景与已有证据

当前 Sound 发音库已提供，与 COL 文字词典分别记录来源。js-mdict 6.0.6 已抽取94条真实英美音样本，实际 Speex 解码、MP3 转换和再次解码通过；Chrome／Edge 共188次基础播放检查通过。原始 Speex 样本直接播放失败。上述证据不涵盖全库、人工听感、物理扬声器、正式Session／Range接口或数据权利。

M02 当前部分实施、质量阻断，正式文字包、V5及Java查询未交付；不能因音频样本可播放而改变该状态。ADR-0004 的子词条、entry-v2 和提取质量决定保留。

## 决定

1. 新增独立 A02-01～06，分别管理映射、离线处理、存储、接口、卡片与验收。不向 M02-01～06 加任务，不改其验收条件；旧历史证据不改写。
2. 采用离线 Speex→MP3，初始单声道22050Hz、48kbps，FFmpeg只在离线工具运行，线上Java读取私有MP3并由浏览器原生Audio播放，不在请求路径转码。
3. 使用独立音频包和数据集／资源／词头口音映射／活动指针，不改变 M02 文字包身份。迁移在文字V5之后追加，执行前核对实际编号。
4. 使用Session保护的GET／HEAD `/api/v1/dictionary/audio/{audioId}`，支持有界Range、ETag和私有缓存重新验证；不开放存储目录、任意路径或公共导入接口。
5. 关联实际展示组件词头或已确认lemma，明确口音和独立来源；不将ran录音静默当run，不自动用TTS替代。音频失败局部降级，不影响文字、翻译与收藏。
6. 离线底座可先开展；查询和卡片接入等待M02正式查询及M05。底座与完整链路分别验收，人工试听／全库完整性／权利状态单列。

## 替代方案及取舍

| 方案 | 不作为首版路线的原因 |
|---|---|
| 浏览器直接播放Speex | 所测Chrome／Edge真实样本媒体错误4；改MIME无效 |
| 浏览器WASM解码 | 引入解码器、CPU／内存与许可证治理；当前离线转换路线有样本证据，无必要新增客户端链路 |
| 每次请求在线转码 | 增加延迟、子进程及配额风险，重复消耗CPU，故障牵连文字查询 |
| 合并进M02包和验收 | 音源不同、生命周期不同；倒改原任务范围与身份，影响已完成工作追溯 |
| 自动TTS或猜词形替换 | 改变录音来源／内容语义，不能代替当前真实发音资源验收 |

MP3样本占用约为源压缩资源2.39倍，不以节省空间作为理由；重采样不意味着提高原录音质量。全库预算、映射歧义、丢失资源、人工听感和授权仍有风险，依A02门槛验证；存在失败时不得宣传全库可用。

## 验证及后果

直接复用历史94条和188次记录，不重复同一轮完整样本实验。新增实现需验证全量对账／断点、文件和数据库一致性、并发切换、鉴权／Range／缓存以及正式卡片的停止生命周期。证据独立归档 `validation/implementation/a02/`，本次不创建通过记录。

本决定仅收敛工程路线；未执行转换、迁移或功能开发。未来改变编码参数、数据身份或播放方式需新增修订和对应验证，不能覆盖既有产物或追认未验收能力。
