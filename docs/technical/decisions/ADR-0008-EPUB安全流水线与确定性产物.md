# ADR-0008：Java EPUB 安全流水线与确定性不可变产物

状态：已采纳（用户于 2026-11-23 确认）；日期：2026-11-23。
关联需求/技术设计：[PRD V1.1](../../requirements/prd/PRD-v1.1.md) 第 4.1、12.2、12.7、14.1 节；[系统技术设计](../architecture/Readict-V1.1-系统技术设计.md) 第 7.1、13.3、13.6、14.2、15.1、17.3 节；[模块化开发计划](../implementation/Readict-V1.1-模块化开发计划.md) M03。
关联任务：M03-01～M03-06。本文不改变 PRD 范围，不把 M03 标为完成。

## 背景与约束

**【已有事实】** 导入与安全处理的现有证据全部来自浏览器侧：[reader-core importBook.ts](../../../validation/technical/reader-core/src/importBook.ts) 使用 JSZip＋DOMPurify＋`XMLSerializer`，[REPORT](../../../validation/technical/reader-core/REPORT.md) 明确其解压不是流式受限、依赖审计未关闭、清理不等于完整安全边界。正式工程是 Java 服务端，运行环境、解析器、序列化器和攻击面均不同，**不能引用该结论为 Java 流水线背书**（设计第 17.3 节 V03／V04）。

**【工程约束】**

1. 单实例、无 Docker／消息队列前置；导入必须在进程内可中止、可恢复，且不能无界占用堆与 CPU（设计第 6.3、15.1 节）。
2. READY 必须对应完整可读文件与索引；同一输入与版本应生成相同 `artifactHash`（设计第 7.1、13.6 节）。
3. 产物在浏览器内以同源禁脚本 iframe 加载，父页需读取 DOM；安全依赖“入库前清洗＋渲染前校验＋CSP”（设计第 3.2 节）。
4. 预算必须真实阻断，而不是只校验声明值；CPU／内存无法有界时停止模块推进（模块计划 M03 退出条件）。
5. 依赖版本与许可需逐个锁定并记录，不因“能编译”视为通过。

## 候选方案与验证证据

| 方案 | 结论 | 理由 |
|---|---|---|
| 服务端复用 DOMPurify／JSZip（Node 子进程或 GraalJS） | 不采用 | 引入第二运行时与跨语言序列化差异，无法证明字节级确定性；浏览器结论不可直接迁移 |
| 第三方 Java HTML sanitizer（如 OWASP Java HTML Sanitizer）直接采用 | 不作为首选 | 面向普通 HTML，对 XHTML／EPUB 命名空间、内部链接与资源闭合无内建语义；需大量包装后才等价于自定义白名单 |
| JDK JAXP 安全解析＋自建元素／属性白名单＋自建确定性序列化 | **采用** | 只用 JDK 内建解析能力，白名单与序列化行为完全可控、可测、可版本化 |
| 正则过滤 CSS | 不采用 | 设计已明确禁止用正则替代完整安全策略；正则无法正确解析 `url()`、`@import`、嵌套 at-rule |
| 引入 ph-css 解析 CSS AST 后按属性／值白名单重写 | **采用（待锁版）** | 需要真实语法树而非字符串替换；库版本与许可须在 M03-01 核对并写入 POM |
| 直接透传原 EPUB 字节作为阅读产物 | 不采用 | 无法移除脚本／远程资源，也无法保证确定性；违背“产物不可变且可复现” |
| 对产物做二次压缩或其他“接近即可”的确定性近似 | 不采用 | 摘要不一致时必须显式升 `pipelineVersion`，不能以“内容看着一样”验收 |

**【待验证】** JDK 内建 `Deflater` 与 XML 序列化在同一 JDK 大版本内字节一致；跨 JDK 大版本是否一致未知。ph-css 的精确版本、传递依赖与许可尚未在本工程锁定。

## 决定及理由

1. **解析**：`java.util.zip` 读取中央目录做快速预检，随后以读取流累计真实输出字节；达到预算立即中断。XML 用 JDK JAXP 且固定安全参数（禁 DTD、禁外部实体、禁外部 schema、禁网络）。
2. **清洗**：XHTML／SVG 逐元素、逐属性白名单；删除脚本、事件属性、表单、嵌套框架、远程 URI、`data:` URI、隐藏内容；CSS 经语法解析后按属性／值白名单重写，删除 `@import`、远程 `url()`、`@font-face`、动画与覆盖式定位。
3. **资源闭合**：只保留 spine XHTML、被保留内容实际引用的图片／CSS、封面；脚本、字体、音视频、未知媒体类型一律剔除并计数，不生成悬空引用。
4. **确定性**：自建序列化器（固定 XML 声明、固定属性顺序、固定转义、无注释与处理指令）；ZIP 重建时 `mimetype` 为首条且 STORED，其余条目按路径排序、固定时间戳、固定 DEFLATE 级别、不写 extra field。
5. **产物身份**：`pipelineVersion=epub-safe-v1` 与 `artifactHash` 一同持久化；同输入同版本两次生成的 `artifactHash` 必须一致，否则该次导入不得 READY，并以 `EPUB_ARTIFACT_UNDETERMINISTIC` 失败。
6. **文本索引**：产物内附版本化 `index.json`（schema `readict-text-index-1`），记录每个块的 `blockId/text/utf16Length/textHash` 与句范围；浏览器 DOM 与索引逐字一致是保存快照的前置条件。
7. **封面**：只接受包内声明封面且为 JPEG／PNG，按魔数与尺寸校验后**原字节保存**，不重编码；SVG 封面拒绝。重编码留作后续独立评估。
8. **CSP**：在产物每个 XHTML 文档 head 注入禁脚本、禁连接、禁框架的 CSP `meta`，作为清洗之外的纵深防护。

## 影响、代价与风险

- 阅读产物通常比源文件大（文本重新 DEFLATE，压缩率受固定参数限制）；需要独立产物体积预算并真实测量。
- 白名单必然造成部分合法排版降级（复杂 CSS、MathML、自定义字体、音视频、脚本化交互）。第一版明确不支持，失败或降级必须可解释，不能静默。
- 确定性只在“同机同 JDK 同版本规则”内承诺；跨 JDK 或规则调整必须升 `pipelineVersion`，旧 CFI 不自动复用。
- 自建序列化器与白名单是安全关键代码，必须由 V03／V04 的恶意样本矩阵验证；未通过前不得对外发布该能力。
- 原字节封面保留了图片解码器攻击面；需依赖浏览器解码与响应头限制，残余风险在 M09 安全清单登记。
