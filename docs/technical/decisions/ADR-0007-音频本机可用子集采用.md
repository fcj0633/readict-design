# ADR-0007：独立音频库采用本机可用录音子集

状态：已采纳；日期：2026-11-22。依据：A02 全量处理中，用户明确确认“允许一定的缺陷录音，继续开发验收”。补充 ADR-0005，不改变 COL 文字身份、质量结论或活动数据集。

## 决策与边界

完整扫描源索引和资源，保留所有结果。使用范围增加 LOCAL_MVP，采用策略 audio-local-subset-v1。源格式、PCM、源信号或输出质量未通过的资源逐条隔离，附物理序号、资源键、源摘要、字节数和错误码；依赖它的映射记录警告并不进入可播放目录。其他可用录音可继续验收，无需为每条源录音缺陷再次请求排除。此授权不代表降低 RMS、峰值、时长、解码或完整性门槛，也不代表任意资源故障可豁免。

可隔离错误码仅为 AUDIO_SOURCE_FORMAT、AUDIO_PCM_INVALID、AUDIO_SOURCE_SIGNAL、AUDIO_OUTPUT_QUALITY、AUDIO_SOURCE_DECODE。AUDIO_SOURCE_DECODE 仅在独立的严格源解码命令（-xerror、-err_detect explode）非零退出且 Speex 解码器明确报告无效数据包时成立，保存 ffmpeg-strict-speex-v1 证据；日志超限本身不证明损坏。普通进程失败、超时、未知错误、源变化、计数、摘要、身份和路径错误继续阻断；续跑可重新处理基础设施故障，不把它当词典问题。None、坏编码等文字结论不由本决策改变。

默认按完整技术范围校验。LOCAL_MVP 在 Node 校验、Java 校验、导入和激活时必须显式使用 --allow-local-subset；参数只开放已登记的采用策略，不跳过其他检查。approvalRef 绑定本次用户确认，转换器身份包含 /local-subset-v1，完整范围采用 /full-v1，避免同一身份对应不同采用策略。

technicalEligible 表示包内数据满足声明范围，completeSourceEligible 表示全部音频候选成功，两者分开。releaseEligible 继续为 false；humanReview=NOT_PERFORMED、rightsReview=UNVERIFIED，snapshotAllowed=false、distributionAllowed=false。READY 仅表示声明范围内文件和数据库完整，不表示人工听感或分发权利通过。

## 保持的技术约束

每条 MDX 索引在 dispositions 中有唯一结果，全部 MDD 资源以成功音频、隔离音频、非音频三个互斥集合对账。mapping 保留词头、口音、DOM 位置、源序号、资源实际匹配规则；不通过删词尾、资源文件名或猜测填补关系。

源 MDD 显式声明 KeyCaseSensitive=No，因此仅对唯一的实际资源候选采用 ASCII 大小写兼容匹配，冲突继续报错。遇到不合法百分号转义，仅允许与容器中已存在的字面键完全匹配，并经过相同路径检查；不进行宽泛 URI 修复。普通 URI 仍只解码一次，+ 不变为空格。词缀及收缩标记不能剥离标点后冒充普通词头。

FFmpeg 使用两个有界进程，显式 -map 为每个输入分别产生输出，不连接录音。每次最多128个独立输入，使用隔离工作目录和短文件名控制 Windows 参数长度；同时最多两个 FFmpeg 进程，逐条读取 PCM 后释放，不把整批 PCM 载入内存。批量路径保留逐资源源解码、信号、MP3 格式、再解码及时间比较，进程失败回到原单资源检查。参数数组、30秒超时、输入与解码上限不变；相同录音在单资源与批量路径的媒体摘要须对照一致。处理顺序与批量大小不参与产物身份，输出必须与全新第二次转换一致。参考 [FFmpeg 官方多输入与逐输出参数规则](https://ffmpeg.org/ffmpeg.html)，未复制第三方代码或增加生产依赖。

## 验收与未交付范围

两次全量产物、Node／Java 独立校验、MySQL 事务／续跑／租约／切换、真实 Session 鉴权 HTTP 及浏览器播放分别验收。合成测试媒体字节只证明传输，不能替代实际音频播放。正式卡片待 M05，人工试听与数据权利保持独立未决项。

实施进度与最终结论见 [A02 验收入口](../../../validation/implementation/a02/README.md)。本 ADR 采纳策略不等于全部实现已验收。

## 源缺陷复核补记

截至本轮阶段复核，Bavaria、Coahuila 两个资源经现有独立 readmdict 路径得到与 js-mdict 相同的键、长度及摘要，严格 FFmpeg 解码明确报告无效数据包；原普通命令的重复错误日志触及64KiB上限。只将这种已验证类型记为源解码问题，不把日志或进程上限直接加入豁免。另有部分源文件实际为双声道且可解码，归入本轮输入范围不支持，不能称为损坏。其余成功录音不受上述问题连带影响，最终全源数量以验收报告为准。

## 2026-11-23 MVP 验证范围调整

用户后续明确优先快速完成 MVP，基本可用即可。本轮停止第二次全量转换、重复全量扫描、整库测试导入和大规模浏览器／性能验证，采用已完成的第一轮包，保留导入内置完整性与安全检查，确认开发库启用及少量真实鉴权播放。上文双全量一致性等仍为未来完整复验目标，本轮不声称已通过。现有正式测试保留，未做项目在验收记录中明确列出。未人工试听、权利未核实及正式卡片待 M05 的状态不变。

最终 MVP 实现冻结清单、在私有发布时逐文件校验，不生成整库中间副本；READY 复用发布结果，以计数、断点和 owner 租约为条件，不再逐文件重扫。完整断点续跑复用同 manifest 的发布结果；正常文件关闭与原子改名保留，逐文件强制同步刷盘、外部删除／损坏和断电恢复全量复验后置。播放仍按需校验实际媒体、拒绝缺失或变化文件。此收敛只适用于本机 MVP，不能视为已通过原完整存储故障矩阵。
