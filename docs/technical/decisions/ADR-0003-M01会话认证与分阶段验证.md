# ADR-0003：M01 会话认证与分阶段验证

状态：**已采纳工程方案，M01 集成与验收尚未执行**。日期：2026-11-19。

确认依据：用户要求基于真实 M00 编写可实施的 M01 文档，并确认“核心账号 → 本地模拟验证 → 真实短信／邮件通道”的分阶段方案。本决定细化系统设计的 Session／CSRF 和恢复规则，不改变 PRD 功能范围，不替代 ADR-0001／ADR-0002 的持久层与环境决定。

关联：[M01 执行文档](../implementation/M01-用户认证与个人设置执行文档.md)、[系统设计](../architecture/Readict-V1.1-系统技术设计.md)、[模块计划](../implementation/Readict-V1.1-模块化开发计划.md)、[M00 证据](../../../validation/implementation/m00/README.md)。

## 背景与证据边界

正式应用已有 Java 21／Boot 4.1.2、MyBatis-Plus／XML、本机数据库保护及统一 Problem Details。M00 安全链目前拒绝业务入口，尚无用户和 Session 业务。已有持久层能力不证明认证上下文跨请求恢复、CSRF、真实所有权或密码恢复已经通过。

官方 [Session 自动配置](https://docs.spring.io/spring-boot/reference/web/spring-session.html)提供 Boot 4 的 JDBC Starter；[Security 持久化](https://docs.spring.io/spring-security/reference/servlet/authentication/session-management.html)要求自定义登录显式保存上下文；[CSRF 文档](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)说明默认防护及 token 生命周期。它们是方案依据，项目仍需未来真实 HTTP／数据库验收。

## 决定

1. 采用 Boot BOM 管理的 `spring-boot-starter-session-jdbc`，复用原 DataSource。V1 不修改，V2 建用户／设置，V3 取实际 Session JAR 的官方 MySQL schema，V4 建挑战／恢复／限流；V4 在核心登录限流启用前迁移。只由 Flyway 管表，不启用框架自动初始化。
2. JSON 登录执行 AuthenticationManager、SessionAuthenticationStrategy（Session ID 轮换及 CSRF 失效）、创建最小 Serializable 主体，并显式调用共享 SecurityContextRepository.saveContext。主体只含 UUID、authVersion、认证时间和必要身份，不含密码哈希。
3. Session 空闲 30 分钟、绝对 7 天；每个认证请求检查用户状态／authVersion／绝对时间。改密和重置递增版本立即拒绝旧 Session；后台清理失败可重试，不能以清理最终完成代替即时失效。
4. 保留 Session CSRF，匿名 csrf GET 提供掩码 token，前端提交指定头，登录／退出后重新获取。框架 LogoutFilter 处理 POST 退出并返回 204。变更请求不因网络／403 无条件自动重发。
5. 注册不自动登录，联系方式初始未验证。恢复必须是绑定账号、目标和用途的短时证明，再换一次性高熵恢复凭证；重置和消费同一事务。
6. VerificationSender 分离不可用、测试捕获、本地受限 outbox 和未来真实适配器。模拟流程带 DEV_LOCAL 信任模式，不能把真实 verified 置真；开发凭证只在显式 dev/test 配置接受，真实环境拒绝。
7. 真实供应商、凭据、模板／费用及实际发送验证待定；可先验收核心和模拟流程支持后续模块，未完成真实所有权及恢复不得标 M01 全范围完成。

## 替代方案与理由

- JWT／刷新令牌：增加撤销、轮换和客户端存储复杂度，当前同源单体无需引入；JDBC Session 直接复用 MySQL。
- 只调用 SecurityContextHolder：仅当前线程有效，可能造成登录成功但下一请求匿名，故明确 repository 保存与跨请求测试。
- 关闭 CSRF 或调试时全放行：掩盖 Session 架构下的风险，改用明确 token 获取／轮换契约。
- 一开始阻塞所有开发直至供应商接入：没有必要阻止本机核心和业务状态机验证；但模拟不能作为真实所有权证据。
- 万能验证码／公开取码接口／日志打印：容易被带到部署环境或泄露，不采用；测试使用进程内捕获，手动 dev 仅受限 outbox。
- 只删 Session 表行失效：删除失败或竞争会延迟撤销，故 authVersion 为正确性保障，物理清理为回收手段。

## 风险和验收门槛

Session 序列化、Cookie、框架策略装配和掩码 token 均有集成风险，必须用真实 Cookie jar／HTTP／MySQL 验证。密码哈希成本需要本机校准；限流计数、挑战消费、设置版本和改密并发需要真实事务测试。DEV_LOCAL 误用会破坏所有权语义，必须有启动拒绝、数据模式检查和负向测试。真实通道隐私、费用、可达性及所有权证明仍是账号全范围验收门槛。

本次只编写文档并静态检查，不创建数据库、不安装或集成 Session、不执行 M01 用例、不发送信息。未来结果按执行文档归档，不能把本 ADR 的“已采纳”解释为“已实现”。
