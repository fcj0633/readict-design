## 3. M00-02：本机数据库、账号及配置

### 3.1 管理员准备与 SQL 边界

前置：管理员凭据由用户在实际执行时输入，不在命令行、聊天、日志或 Git 中填写。工作目录不影响 MySQL 命令；连接本机，明确交互式 `-p`：

```powershell
mysql --host=127.0.0.1 --port=3306 --user=root -p
```

先在客户端只读确认：

```sql
SELECT VERSION(), @@port, @@character_set_server, @@collation_server;
SELECT SCHEMA_NAME FROM information_schema.SCHEMATA
WHERE SCHEMA_NAME IN ('readict_dev','readict_test');
```

若库或账号已存在，先核对用途与权限，不能删除重建或静默改密码。以下为首次准备示例；`REPLACE_*` 必须在受忽略的本地脚本中换成各不相同的真实值，不得照抄占位密码运行或提交该本地脚本：

```sql
CREATE DATABASE readict_dev CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;
CREATE DATABASE readict_test CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_bin;

CREATE USER 'readict_dev_app'@'127.0.0.1' IDENTIFIED BY 'REPLACE_DEV_APP_PASSWORD';
CREATE USER 'readict_dev_migrate'@'127.0.0.1' IDENTIFIED BY 'REPLACE_DEV_MIGRATE_PASSWORD';
CREATE USER 'readict_test_app'@'127.0.0.1' IDENTIFIED BY 'REPLACE_TEST_APP_PASSWORD';
CREATE USER 'readict_test_migrate'@'127.0.0.1' IDENTIFIED BY 'REPLACE_TEST_MIGRATE_PASSWORD';

GRANT SELECT,INSERT,UPDATE,DELETE ON readict_dev.* TO 'readict_dev_app'@'127.0.0.1';
GRANT SELECT,INSERT,UPDATE,DELETE ON readict_test.* TO 'readict_test_app'@'127.0.0.1';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,ALTER,DROP,INDEX,REFERENCES
ON readict_dev.* TO 'readict_dev_migrate'@'127.0.0.1';
GRANT SELECT,INSERT,UPDATE,DELETE,CREATE,ALTER,DROP,INDEX,REFERENCES
ON readict_test.* TO 'readict_test_migrate'@'127.0.0.1';
```

账号 Host 必须与实际 TCP 连接匹配；遇到 Access denied，核对 MySQL 匹配到的账户和授权，不以 `%`／全库授权掩盖问题。运行账号不允许 CREATE／ALTER／DROP；迁移账号只拥有对应 schema 权限，不是全局管理员。Flyway clean 全程禁用；DROP 权限仅为后续受控迁移需要，不授权测试随意清库。

验证四个账号时分别 `mysql ... --user=<对应账号> -p <对应库>`，执行 `SELECT DATABASE(),CURRENT_USER(),@@version` 和 SHOW GRANTS；不能访问另一业务库。无表时不靠创建临时业务表验证，迁移完成后再查元信息；权限负向检查用无副作用权限检查或在测试库中受控断言，不在开发库尝试删除已有数据。

### 3.2 环境变量与秘密加载

环境变量契约：DB_APP_USER／DB_APP_PASSWORD、DB_MIGRATION_USER／DB_MIGRATION_PASSWORD。开发与测试分别在独立终端或测试启动脚本中设置对应账号，不共用默认密码。DB_HOST／DB_PORT 如提供，只允许本机地址和经确认端口；库名不由任意环境变量自由切换，profile 明确指定。

PowerShell 可用以下方式在当前终端输入秘密（不回显密码）：

```powershell

$env:DB_MIGRATION_USER = 'readict_dev_migrate'
```

该终端中的子进程可读环境变量，停止应用后关闭终端或清理对应变量；不要输出环境全集。`.env.example` 只有变量说明，**Spring Boot 不自动读取 .env**。也可使用受忽略的 `.local/` PowerShell 配置脚本，README 明确先在当前终端加载；不能把密码写进 Maven 参数或 POM。未来正式部署采用专门秘密配置，本机做法不自动成为生产方案。

## 4. M00-03：迁移、Mapper/XML 与事务闭环

### 4.1 扫描和职责

在主类使用 `@SpringBootApplication`；独立配置 `@MapperScan(basePackages="com.readict.*.infrastructure.persistence.mapper")`。该模式只扫描约定模块包，新增嵌套结构时同步调整，测试须断言 SystemMetadataMapper Bean 可注入。Mapper 接口和 XML namespace 完全匹配；XML 放 resources 而非 Java 目录。

调用方向：Controller → 应用服务 → Repository → Mapper → DataSource。M00 无用户业务；未来 Repository 显式带 userId 条件，不能直接把 BaseMapper 暴露给 Controller。Spring 事务在应用服务公共方法上，禁止同类自调用绕过代理；所有业务 Mapper 复用同一 DataSource。

默认不启用代码生成、分页／多租户／乐观锁／逻辑删除插件；当前游标分页和显式版本 SQL 不需要这些插件。未来确需插件时单独登记与验证，不能把插件当用户隔离或唯一约束。

### 4.2 第一条迁移

文件：`src/main/resources/db/migration/V1__create_system_metadata.sql`。只建元信息表和固定基线行：

```sql
CREATE TABLE system_metadata (
  metadata_key VARCHAR(64) CHARACTER SET ascii COLLATE ascii_bin NOT NULL,
  metadata_value VARCHAR(255) NOT NULL,
  version BIGINT NOT NULL DEFAULT 0,
  updated_at DATETIME(3) NOT NULL,
  PRIMARY KEY (metadata_key),
  CONSTRAINT ck_system_metadata_version CHECK (version >= 0)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_0900_bin;

INSERT INTO system_metadata(metadata_key,metadata_value,version,updated_at)
VALUES ('application','readict',0,UTC_TIMESTAMP(3));
```

Flyway 默认自建 flyway_schema_history，除此之外 M00 无用户／Session／书籍表。V1 在首次执行后不可改写；后续模块从 V2 递增，新迁移处理修正。不要设置 baseline-on-migrate=true 绕过已有未知表；发现非空陌生库立即停止确认。

### 4.3 Entity、BaseMapper 和 XML 示例

实体使用普通 JavaBean，提供完整 getter/setter 或等价生成代码；不因使用 record 影响 MyBatis／MP 可变属性映射：

```java
@TableName(value = "system_metadata", autoResultMap = true)
public class SystemMetadataEntity {
    @TableId(value = "metadata_key", type = IdType.INPUT)
    private String metadataKey;
    @TableField("metadata_value")
    private String metadataValue;
    private Long version;
    @TableField(value = "updated_at", typeHandler = UtcInstantTypeHandler.class)
    private Instant updatedAt;
    // 实施时补齐所有 getter/setter；保存前明确赋 UTC 时间和版本。
}
```

接口完整包名为 `com.readict.operations.infrastructure.persistence.mapper.SystemMetadataMapper`：

```java
public interface SystemMetadataMapper extends BaseMapper<SystemMetadataEntity> {
    SystemMetadataEntity selectMetadata(@Param("key") String key);
    int updateIfVersionMatches(@Param("key") String key,
        @Param("value") String value, @Param("expectedVersion") long expectedVersion,
        @Param("updatedAt") Instant updatedAt);
}
```

XML 采用 MyBatis 原生格式；DOCTYPE 指向框架定义，不允许从用户输入构造 Mapper XML：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "https://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="com.readict.operations.infrastructure.persistence.mapper.SystemMetadataMapper">
  <resultMap id="metadataResult" type="com.readict.operations.infrastructure.persistence.entity.SystemMetadataEntity">
    <id property="metadataKey" column="metadata_key"/>
    <result property="metadataValue" column="metadata_value"/>
    <result property="version" column="version"/>
    <result property="updatedAt" column="updated_at"
      typeHandler="com.readict.shared.persistence.typehandler.UtcInstantTypeHandler"/>
  </resultMap>
  <select id="selectMetadata" resultMap="metadataResult">
    SELECT metadata_key,metadata_value,version,updated_at
    FROM system_metadata WHERE metadata_key=#{key}
  </select>
  <update id="updateIfVersionMatches">
    UPDATE system_metadata
    SET metadata_value=#{value},version=version+1,
        updated_at=#{updatedAt,jdbcType=TIMESTAMP,typeHandler=com.readict.shared.persistence.typehandler.UtcInstantTypeHandler}
    WHERE metadata_key=#{key} AND version=#{expectedVersion}
  </update>
</mapper>
```

只有简单、权限已由 Repository 限定的操作使用 BaseMapper；复杂查询、JOIN、`FOR UPDATE`、去重和条件更新显式 XML。返回更新行数 0 表示冲突／不存在，应用服务据上下文区分，不以无异常作为更新成功。SQL 全部绑定 `#{}`，不得以 `${}` 放用户筛选／排序值。

### 4.4 UUID 与时间 TypeHandler

正式业务主键仍为应用生成 UUID、数据库 BINARY(16)，MP 用 `IdType.INPUT`；不自动改成 BIGINT 雪花 ID。`UuidBinaryTypeHandler` 需 `@MappedTypes(UUID.class)`、`@MappedJdbcTypes(value={JdbcType.BINARY,JdbcType.VARBINARY},includeNullJdbcType=true)`，编码固定“mostSignificantBits 后 leastSignificantBits，各 8 字节 big-endian”，禁止默认为字符串或交换字节：

```java
static byte[] uuidBytes(UUID id) {
    return ByteBuffer.allocate(16)
        .putLong(id.getMostSignificantBits()).putLong(id.getLeastSignificantBits()).array();
}
static UUID uuidValue(byte[] bytes) {
    if (bytes == null) return null;
    if (bytes.length != 16) throw new IllegalArgumentException("Invalid UUID bytes");
    ByteBuffer b = ByteBuffer.wrap(bytes);
    return new UUID(b.getLong(), b.getLong());
}
```

实施时继承 `BaseTypeHandler<UUID>`，实现 setNonNullParameter 与 ResultSet（列名／列序号）及 CallableStatement 三个 getNullableResult，null 返回 null；UUID 参数绑定 BINARY，所有 UUID 实体 `autoResultMap=true`。M00 用测试专用 UUID Entity 检查 TableInfo／自动 ResultMap 已关联正确处理器，并用只读 XML 参数往返验证数据库类型；M01 创建首张真实 UUID 业务表后追加 BaseMapper 写入／读回检查。M00 不声称已验证不存在的业务表映射，也不为此预建业务表。

`UtcInstantTypeHandler` 继承 `BaseTypeHandler<Instant>`，添加 `@MappedTypes(Instant.class)` 与 `@MappedJdbcTypes(value=JdbcType.TIMESTAMP,includeNullJdbcType=true)`，读写使用 `Timestamp.from(instant)`／`toInstant()` 与每次新建的 UTC Calendar，调用带 Calendar 的 setTimestamp／getTimestamp；三种读取路径及 null 均处理。MySQL DATETIME(3) 存储没有自带时区，因此统一 UTC 并将比较截断至毫秒；不能共享非线程安全 Calendar 或按操作系统时区转换。DTO 输出 ISO-8601 UTC。

测试专用 `TypeProbeMapper` 放测试代码和 mapper-test XML，用 `SELECT #{value,jdbcType=BINARY,typeHandler=...}` 往返 UUID，用绑定时间的 SELECT／CAST 往返 UTC 毫秒时间，注册对应 resultMap／handler；不建正式 probe 表，不把测试 Mapper 打包到 main。null、非法字节长度、不同默认时区以及 Java UUID 与 SQL HEX 对照均列用例。

### 4.5 测试库启动保护与真实事务

数据库 IT 只使用 `@SpringBootTest`＋test profile，不使用 H2、内嵌库替换，也不靠 `@MybatisTest` 的自动回滚证明应用事务。测试类 `*IT` 由 Failsafe 执行。必须实现以下保护：

1. 测试专用 `ApplicationContextInitializer` 在上下文 refresh、DataSource／Flyway 自动配置之前检查 test profile，解析有效 datasource URL 的 host、port、schema，以及 Flyway 有效 URL；只允许本机、确认端口、readict_test。将其显式注册到每个数据库 IT 的测试上下文。默认 profile／缺少配置立即失败。
2. 连接建立后、任何清理 SQL 之前，通过只读 Mapper `SELECT DATABASE()` 和连接元信息复核。不能仅检测 URL 包含字符串 `test`，也不能等 Flyway 已访问错误库后才检查。
3. 不运行 DROP DATABASE／Flyway clean。测试写入唯一 `it_<UUID>` 前缀元信息行，按这些精确 key 清理，绝不全表删除；application 基线行不改。
4. 测试账号使用 readict_test_app／readict_test_migrate，不回退 dev／root。误配为 dev 的负向测试只运行前置配置校验器，确认未创建连接／执行迁移，不实际访问开发库。

真实回滚用例：测试配置中注册两个独立 Bean，一个应用服务经 Spring 代理执行 `@Transactional`，先 BaseMapper insert，再 XML update，最后主动抛 RuntimeException；测试方法本身**无 @Transactional**，捕获错误后从独立非事务调用查不到插入行，证明应用事务回滚。另有正常 commit 用例证明写入可见，不能只有“全部没写进去”的假阳性。测试专用失败服务不进入正式 main，不开放 HTTP 故障入口。

## 5. M00-04：API、错误、日志与前端连通

### 5.1 系统状态契约

实现 `GET /api/v1/system/status`。Controller 调应用服务，服务经 Repository 调 Mapper 读取 application 基线行，核对 value=readict；不是仅返回常量或只连通 TCP。成功 200：

```json
{"status":"UP","service":"readict","requestId":"8b5a4080-e5ee-4e90-a3bd-676bc8dde713"}
```

数据源不可用／基线行不存在或不符时返回 503、`application/problem+json`：

```json
{
  "type":"urn:readict:error:system-not-ready",
  "title":"服务暂未就绪",
  "status":503,
  "code":"SYSTEM_NOT_READY",
  "detail":"请稍后重试。",
  "requestId":"8b5a4080-e5ee-4e90-a3bd-676bc8dde713",
  "retryable":true
}
```

不返回数据库产品／账号／地址／表内容、堆栈或内部 SQL。启动前数据库不可用应因 Flyway／连接检查失败而终止，此时状态接口根本不监听；“接口 503”用于应用已运行但依赖随后不可用等情形，不能用一个没启动的进程断言 HTTP 503。

### 5.2 错误、requestId 与日志

实现请求过滤器：接受合法 UUID 形式的 X-Request-Id，否则生成新 UUID；返回 X-Request-Id，同时放 request attribute／MDC，finally 清除，异步分发不重复覆盖。禁止直接把任意长／含换行客户端头放日志。统一 ControllerAdvice 映射参数错误、验证失败、系统就绪失败及未知异常；Security 入口和拒绝处理器也输出相同 Problem Details，而不是 HTML 登录页。

日志包含 requestId、方法／安全路由、状态、耗时和安全错误码；不记录密码、Cookie、认证头、连接 URL 查询参数、MyBatis 参数、正文全文、翻译内容。生产禁 SQL 参数打印和 stdout SQL 日志；开发默认也不打开详细参数。保留异常堆栈仅内部受控日志且不能包含秘密，HTTP 不透传异常 message。

### 5.3 存活、就绪和临时安全配置

定义 MetadataHealthIndicator（bean 名 metadata）检查同一基线行。`/actuator/health/liveness` 仅依进程生命周期；`/actuator/health/readiness` 包括 readinessState、db、metadata。二者 show-details=never，根 health、env、configprops、beans 等未在允许清单，不意外暴露管理信息。

M00 独立 SecurityFilterChain：仅 GET system/status、liveness、readiness 允许匿名；必要 ERROR dispatcher 允许进入统一错误响应，其余请求拒绝（401／403 Problem Details）。关闭 formLogin 和 httpBasic，不输出默认登录页面；排除／覆盖默认 UserDetailsService 自动创建并加入启动测试确保无生成默认密码。CSRF 不全局关闭，M00 没有公共写接口。仅监听回环地址；M01 接入真实用户认证、CSRF token 和角色策略时显式替换临时边界，不把临时 allowlist 当完整认证。

### 5.4 前端状态页及 API 客户端

M00 最小界面仅用于开发连通：显示连接中／服务可用／暂不可用及 requestId，提供手动重试，不提前制作书架或账户页面，也不显示数据库实现细节。未来业务首页替换此视图。

`src/lib/api.ts` 最小行为：

```ts
export type ApiError = {
  status: number; code: string; title: string; requestId?: string; retryable: boolean;
};
export async function getSystemStatus(signal?: AbortSignal) {
  const response = await fetch('/api/v1/system/status', {
    credentials: 'same-origin', signal, headers: { Accept: 'application/json' },
  });
  // 实施时按 Content-Type 安全解析，503 problem 转 ApiError；
  // 非 JSON / 网络断开 / Abort 分别处理，不能把 response.ok=false 当成功。
  // 返回校验后的 {status:'UP',service:'readict',requestId:string}。
  return readStatusResponse(response);
}
```

实际实现 `readStatusResponse` 和类型校验，禁止直接对不可信 JSON 强制断言类型。页面卸载／重试取消旧请求，迟到响应不覆盖新状态；网络错误显示重试，不把原始服务器 HTML 插入 DOM。客户端仅 GET，M01 再增加实际 CSRF token 获取／轮换和会话过期处理，不写假 token。


代理不 rewrite `/api`，后端保留 /api/v1 前缀。前端不直接请求 8080，不设置宽泛 CORS，不混用 localhost 和 127.0.0.1。测试 api.ts 的 200、503、非 JSON、网络失败、取消和重试竞态；使用 Mock fetch 只能证明客户端分支，另做真实代理检查。
