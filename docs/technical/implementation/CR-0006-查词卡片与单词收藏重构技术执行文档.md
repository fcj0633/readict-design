## 2. 词典释义分组设计

### 2.1 现有实现与结论

| 实际位置 | 已有能力及问题 |
| --- | --- |
| tools/dictionary-import/src/extract.mjs | 遍历 major/paragraph，将有效释义段落作为 sense，生成 rawPos、pos、zh、providerOrder、sourceLabel、labels、sourceRange、boundaryEvidence；zh 已提取，不是单个中文词 |
| tools/dictionary-import/src/bundle.mjs | 生成带 senseId/entryId/senseKey 的 senses.jsonl，允许 rawPos，保留整个 sense |
| lexical/core/DictionaryImporter.java | parameters 保存完整 sense JSON 到 dictionary_sense.metadata_json |
| resources/mapper/lexical/DictionaryMapper.xml | findEntries 按 source_ordinal/section_order/component_order 排序，findSenses 按 entry_id/provider_order 取 metadata |
| lexical/core/LocalDictionaryProvider.java | load 把原 sense metadata 放入 region.senses，copy 在 posHint 有效时优先相同词性；LookupService 深拷贝并补录音/receipt |
| frontend/src/features/dictionary/model.ts | decodeRegion 没有保留 rawPos |
| DictionaryCard.tsx | candidateGroups 以标签选每组第一个 region，region.senses.slice(0,3) 可能遗漏同 lemma 的其他 region |

因此不默认重新解析词典。现有一个 sense 优先视为一个原生释义组，而非拆分中文同义词；同词性不同 sense 不合并。真实 rawPos 可能为原词典英文标签，不保证均为 vt./vi.；没有及物性信息时不猜测。

### 2.2 最小实际数据核验

在有授权的本机活动 COL 数据集只读抽查 3～5 个词：accept（如果已导入）、多 region 同 lemma、词形变换及歧义词。查询例（实际绑定词形）：

~~~sql
SELECT e.entry_key,e.headword,e.lemma_key,e.section_order,e.component_order,
       s.provider_order,s.pos,s.zh,
       JSON_UNQUOTE(JSON_EXTRACT(s.metadata_json,'$.rawPos')) AS raw_pos,
       JSON_EXTRACT(s.metadata_json,'$.sourceRange') AS source_range
FROM dictionary_active a
JOIN dictionary_entry e ON e.dataset_id=a.dataset_id
JOIN dictionary_sense s ON s.dataset_id=e.dataset_id AND s.entry_id=e.id
WHERE a.slot=1 AND e.lemma_key='accept'
ORDER BY e.source_ordinal,e.section_order,e.component_order,s.provider_order;
~~~

如果一条 sense 已经对应完整组，直接用它。如果现有转换器确实拆散或遗漏释义组，对照授权的原始记录及 sourceRange 再修复必要规则，不按中文标点做猜测。只有证据表明需要重导才修改 extract/bundle/验证规则、产出新版本、通过原有离线工具校验和受控激活；不直接修改 READY 数据集，不重导全库作为默认任务。若缺材料，记录实际不能还原的组并用真实信息降级，不宣称已验证全库质量。

### 2.3 前端显示模型及复用

修改 dictionary/model.ts 的 DictionarySense 与 decodeRegion，增加 rawPos: string | null，允许老数据缺失；LookupRegion 可保留 regionOrder/sectionOrder/componentOrder。保留原有边界校验。新增小型 dictionary/sense-groups.ts 与 SenseGroups.tsx：

~~~ts
export interface SenseGroup {
  senseId: string;      // 实际 senseId，查词收藏必须使用
  pos: string;         // 归一化词性（内部）
  rawPos: string | null;
  zh: string;          // 完整组
}
~~~

候选分组使用 lemmaKey（不是仅凭 headword 标签），每个候选关联第一个 region 的索引；选中后收集全部同 lemmaKey 的 region，按响应 regionOrder/原始顺序，组内按 providerOrder。只去重重复 senseId，不凭相同文本/词性合并。可信已有 posHint 时优先将匹配的第一组提升为主要释义，其余保持原词典顺序；当前 ReaderPage 没有可靠 posHint，不另做 AI 消歧。不同 lemma 的词义和音频保持隔离。若原型名无法确认，则使用真实词面，保持原有未命中/歧义处理。

SenseGroups 统一渲染原生 rawPos（缺失时显示归一化 pos 或通用词性，不把 verb 变成 vt.）、完整 zh；不渲染原 HTML。查词默认三组，更多折叠，收藏列表最多三组、窄屏两组，详情全部。每组真实 key；收藏按钮传当前展示主要组的真实 senseId，避免继续使用旧 region.senses[0] 导致保存错误词义。前后端共享相同数据契约，不必做跨语言代码生成或复杂组件框架。

## 3. 查词卡片与阅读器交互实现

### 3.1 词形、词头与信息结构

DictionaryCard.tsx：标题 region.lemma，缺失用 headword 或原文 surface，音标用同候选真实音标。比较 surface 与 lemma（NFC + 忽略普通大小写），不同才显示原文词形；accept/Accept 不重复，accepted/accept 显示 accepted。删除“词头：”行及底部重复 resolvedLemmaKey 文案，但保留内部字段、候选选择。保留原文语境、真实音频、收藏、关闭按钮及必要错误。无额外词典例句。

更多释义采用同一列表前三组下方自然追加；aria-expanded、展开/收起按钮可键盘操作。原已显示释义不改变顺序，展开不重新请求字典、不停止当前音频。

### 3.2 稳定浮层位置

当前 DictionaryCard.useLayoutEffect 依赖 selection,state.data,state.phase,activeRegion,expanded，重新计算 placeCard，造成高度增加后 top 上移。修改 reader/preview/position.ts 与 DictionaryCard：
- 以一次 selection/lookup 为定位周期；loading 可以临时定位，ready/error 首次完成布局后锁定 left/top/maxHeight；展开、收起、收藏状态或候选切换不得重新测量位置。重新查词或另一单词开启新周期，原 resize/翻页关闭机制继续生效。
- 水平继续复用现有左右选边和 margin clamp；纵向预留合理空间后固定 top。不能只删 expanded 依赖而继续用不考虑剩余空间的 maxHeight。
- 参考算法（非强制像素；现有 margin=16、topMargin=72，极矮视口减小顶边距）：

~~~ts
const room = Math.max(1, viewport.height - topMargin - margin);
const cap = Math.min(Math.floor(viewport.height * 0.75), room);
const reserve = Math.min(cap, Math.max(Math.min(measuredHeight, cap), 300));
const top = clamp(anchor.top - 8, topMargin,
                  Math.max(topMargin, viewport.height - margin - reserve));
const maxHeight = Math.min(cap, Math.max(1, viewport.height - margin - top));
~~~

定位结果存 ref/state，第一次 useLayoutEffect 后显示；后续不以展开高度为输入。reader/reader.css scoped .dictionary-card 保持 fixed、max-width:calc(100vw - 32px)，overflow-y:auto、overscroll-behavior:contain，支持时 scrollbar-gutter:stable；内部滚动不带动正文分页/父页面，不主动 scrollIntoView 或重置 scrollTop。初始贴底时预留约300px可读空间，不强制卡片占满。标题和操作在短屏仍可访问。

### 3.3 外部点击关闭与竞态

ReaderPage.closeLookup 已包含 abort lookupAbortRef、递增 lookupIdRef、停止播放器、清空 lookup/activeRegion，复用为唯一关闭入口。
- 父文档：卡片打开时绑定 document pointerdown 捕获监听，通过 card root 或 composedPath 判断是否在卡片内；外部关闭，不 preventDefault，不阻断其他按钮。关闭/卸载解绑。
- iframe：EpubJsEngine.attachSelection 已绑定 pointerup；selectionAt 返回 null 时当前不 emit，改为发送既有 ReaderEvent {type:'selection',selection:null}，无 error 表示普通空白，ReaderPage 关闭卡片而非提示索引失败。点击其他有效单词替换卡片；非主按钮、拖选、正文链接/交互控件保留原行为，不误查词。保留 caret 后单词 Range 矩形校验，避免空白靠近词时误命中。
- selectionAt 可能异步读取 chapterBlocks。新增单调 generation，捕获当前 document/spine，返回时检查仍是最新点击、当前文档、未 dispose；翻页/重排/外部关闭时失效旧选词（例如 ReaderEngine 新增 invalidateSelection，closeLookup 调用）。startLookup 不错误失效本次有效事件。旧 HTTP 响应继续使用现有 lookupId/AbortController 检查，不能因先点词后点空白而复开。
- 不修改 EPUB 正文 DOM、CFI/Range、原文文本索引或分页协议。X/Esc 保留。已提交收藏请求不因关闭卡片而视为业务回滚。

## 5. 两态收藏 API、服务与持久层

### 5.1 路由与契约

沿用 FavoriteController /api/v1/favorites、Session/CSRF、no-store。前后端协同升级；不维持可用的旧追加业务。

| 方法/路径（相对前缀） | 新响应/规则 |
| --- | --- |
| GET /state?lookupId=&senseId= | {state:"NOT_FAVORITED" 或 "FAVORITED",favoriteId:null 或 UUID}，按 lemmaKey 查询主体 |
| POST /state-source | 保留 {bookId,source}，仅唯一可靠匹配已有主体时 FAVORITED，否则现有 FAVORITE_WORD_UNAVAILABLE |
| POST / | Idempotency-Key UUID；{lookupId,senseId,source}；{state,favoriteId,lemmaKey,createdWord,resourceState} |
| DELETE /{id} | 204，按真实主体 ID 幂等删除，禁止跨用户 |

State 未收藏 ID=null，Saved deleted 回执可保留旧 ID 用于对账，但不能当活动 ID。删除 contextId/contextCount/createdContext。SaveRequest 可继续保留原 Java record 的 nullable favoriteId 成员以维持 canonical JSON/hash 兼容；拒绝非 null favoriteId、无 lookupId/senseId 的旧 append 请求，客户端不发送 favoriteId。避免改动旧序列化 hash 导致合法旧回执重试错误；若确需换 hash 方案，要明确版本并禁止旧请求复活。

### 5.2 FavoriteService.java

现有代码 state/stateSource 查 ContextKey、save 接受 lookupId 与 favoriteId 两种请求、persist 每次可能新增 context。修改为：
- state：保留 receipts.find(lookup,user)、draft(senseId) 检查，db.lemma(user,draft.lemmaKey,false) 即决定两态，不查 context 或计数。
- stateSource：保留 owned book、READY artifact、sources.validate、matchWords/由 confirms 使用 lemma/first_surface/历史 formEvidence，唯一可靠匹配才返回已收藏；其他返回现有 409。无词典结果也可取消可靠已有收藏，不能创建未经确认单词。
- save：验证请求及 key，先读有效旧回执，hash 相等直接 replay；否则从 LookupReceiptStore 读取用户所属真实查词回执及合法 senseId，使用 FavoriteDraft 获取词典引用、原型、音标/首义；保留原长度限制及源验证。
- 保留 READ_COMMITTED TransactionTemplate 和既有短暂有界重试。事务内先 lockOwned(bookId,user)、再查回执、核对 book READY/active artifact，sources.validate(artifact,body.source) 并与 lookup.source 完全相等；取真实 book.title，不信客户端例句或书名。SourceView 的定位只用于当次校验，不持久化；不再查 BookChapterMapper 为例句保存章节。
- db.lemma(user,lemma,true)。若已存在：不更新首义，不增加例句，只记录本次回执返回 FAVORITED/createdWord=false。若不存在：insertWord，成功创建者才 insertExample（id、favoriteId、context_kind、真实 sentence/surface、句内偏移、书名、created_at），主体/例句/回执同事务。并发唯一键冲突优先整事务回滚后重试读取胜者，绝不追加例句给胜者；回执并发唯一键同理。例句插入失败必须回滚主体。
- insertReceipt 继续 operation=FAVORITE_SAVE，request hash 和 24h 有效期，context_id NULL、result_json 新 Saved；同 key 不同请求 409 IDEMPOTENCY_KEY_REUSED。
- replay 校验 hash，按旧 favoriteId+user 查询存在性；存在返回 FAVORITED，否则 resourceState=deleted/NOT_FAVORITED；即使同 lemma 已重新收藏也不能把旧 ID 复活或改为新 ID。查词凭据过期不能重新发起未知结果的新 save。
- delete 保留 db.word(user,id,true)、deleteWord、markDeleted 同事务；例句 FK 级联删除。重复 DELETE 同旧 ID 不能删除后来新收藏的 ID。删除不查书或字典。其他用户资源统一缺失错误。

## 6. 收藏完整词义查询

### 6.1 统一 DTO

现有 FavoriteQueries.word 仅返回单一 pos/meaning_snapshot，FavoriteDetail.contexts 包含 anchor。需要新增轻量 FavoriteLexicalView（favorites/application）注入 DictionaryProvider，由 FavoriteQueries 在已有 SQL 分页/归属查询后生成视图：

~~~ts
interface FavoriteWordView {
  id: string;
  lemma: string;
  ipa: string | null;
  groups: SenseGroup[];  // 列表最多3、详情全部
  definitionStatus: 'complete' | 'snapshot';
  dictionaryChanged: boolean;
  createdAt: string;   // 内部保留，不显示
}
interface WordExampleView {
  id: string;
  sentence: string;
  surface: string;
  wordStart: number;
  wordEnd: number;

}
~~~

后端 SenseGroup 投影只包含 senseId、pos、rawPos、zh，不返回完整原始 metadata。snapshot 回退可用 snapshot:<id> 作为内部显示 key，不用作真实查词 senseId。列表 complete 表示已成功解析真实词条，并不表示列表返回全部组。前端验证 UUID、数组/字符串、日期及 UTF-16 句内偏移；历史损坏例句须记录实际异常，显示真实句子而非造高亮或删数据。

### 6.2 词典复用与降级

1. 在 FavoriteQueries.list 真实 SQL 分页后，对当前页投影；detail 先确认归属后再查完整释义。dictionary.lookup(storedLemma,null)，使用已有 LocalDictionaryProvider 活动数据集及按 dataset+query 有界缓存，不调用需要阅读 source 的 LookupService，不伪造阅读位置。只接受 lemmaKey 严格等于保存 lemma_key 的 region，再按原词典顺序及 providerOrder 组织，去重相同 senseId。不同候选不能混入。
2. 同版本可用 entry_key/sense_key 核对原收藏证据。列表前3组，详情全部组；音标优先历史真实 ipa_snapshot，缺失可取匹配当前真实音标。不额外保存完整释义。
3. 活动数据集版本变更且 normalizationVersion 兼容、仍可可靠确认同 lemmaKey，显示当前真实词典并设置 dictionaryChanged；详情可标注“当前词典版本”。归一化版本不同无法确认、未命中、无相同 lemma、词典故障时回退原首义快照，definitionStatus=snapshot，允许只一组并明确提示。不可选第一候选或补造释义。单项失败不令整个收藏列表不可用。
4. 当前 COL bundle rights=UNVERIFIED、snapshotAllowed=false；沿用既有 M06 本机首义快照范围，不扩大持久化完整词典/录音，不修改权利标记、不分发。完整释义仅从本地 Provider 即时读取。
5. 列表不让前端为每项额外查词 HTTP；后端逐页使用现有有界缓存，默认20条，必要时缩短预览展示。先核实一个20条列表正常响应，不预先做批量查询系统或压测；若实际慢再在同一数据集快照下做批量查询，避免过度开发。词典查询不放在收藏写事务中。
