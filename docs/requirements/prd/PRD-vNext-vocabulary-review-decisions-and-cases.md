# Readict 单词复习：待决策事项与业务验收场景

> 关联：[后续版本复习 PRD 草案](PRD-vNext-vocabulary-study-review-DRAFT.md)  
> 状态：**决策候选，均未批准**｜更新：2026-11-23  
> 本文的「推荐」表示可用于人工讨论的默认候选，不是已确认业务规则或技术方案。

## 1. 为什么单独保存此清单

来源材料中已明确用户希望：**词义识别、独立复习、不背单词式多阶段学习、同词多语境分别练习、兼顾有效性与负担**。但现有 V1.1 只保证 lemma 收藏主体与原句快照，不保证每句已经识别出准确义项；竞品研究也无法还原其内部算法。

因此将影响业务判定的决定集中管理。**先决策再验收，再设计技术方案**；未决策事项可在 PRD 草案中呈现，但不得被默认为已批准实现。

| D-09 | 长期间隔策略与反馈映射 | A 固定间隔；B SM-2 类；C FSRS 类；另需定「模糊」与其他算法输入的映射 | 先定评价语义、做同输入模拟；**不预先选算法** | 高 |
| **D-10** | 取消收藏、句子修改、义项重分组的后果 | A 级联删所有学习历史；B 停用任务并保留可追溯历史；C 先冻结再由用户管理 | 在不改变 V1.1「取消收藏删除主体与句子」规则的前提下，**需要明确复习记录的删除/匿名保留策略**；不得出现幽灵待办 | 阻塞 |

**特别说明：** 用户已决定“不同语境可以分别练习”，这不是自动批准 D-01B「每个句子独立 SRS」。复习对象可按含义归组，语境仍可逐句训练。

## 3. 六个必须在正式 PRD 前解决的业务规则

### 3.1 D-01：目标与收藏的关系

已有收藏模型：

```text
UserFavoriteWord(user, lemma)  [V1.1，唯一]
    └── FavoriteWordContext[*] [V1.1，多个原句快照]
```

未来可能追加的业务概念（非数据库表建议）：

```text
ReviewTarget(明确的词义/学习目标) [下一版本候选]
    ├── contexts: 一个或多个语境
    ├── question/answer: 该目标的有效题面及标准
    └── review state: 该目标的训练和间隔历史
```

**讨论例子**：

- `charge` 在 “The shop will charge a fee.” 与 “They charge him with a crime.” 中属于不同含义；若同词一个全局已掌握标记，可能误判第二义。
- `reluctant` 在多条句子中都表达“不情愿”，每条句子都创建一个长期到期卡片会形成不必要的任务量。
- `run`／`running` 的 lemma 归并仍遵循 V1.1；词形变化不自动代表不同义项。
- 同形不同词性有时需区分，不能仅靠词性一致就保证义项一致。

**需批准的业务定义**：一个目标何时创建、何时共享状态、一个目标可挂接多少语境、如何在前端显示「单词数量」与「待复习目标数量」。

### 3.2 D-05：避免用错误词义反复训练

现状：V1.1 收藏首次主要释义快照，但没有要求为**每条**收藏原句记录可靠的独立语境义项。

因此不能把「每句自动生成标准答案」当作既有数据事实。

候选防错流程：
1. 从可信词典及收藏句获取候选义项；
2. 用户或可核验规则确认目标义项与原句对应；
3. 只有**判定依据充分**的目标进入严格评分练习；
4. 不能核验时显示「待确认」或提供非评分式查看，不把 AI 推测作为唯一答案；
5. 若义项后来被修改，历史解释与记忆安排需按 D-10 处理。

是否在首次训练前向用户显式确认所有义项，以及是否因此产生过高操作负担，需原型测试。

### 3.3 D-03：阶段推进的含义

建议先定义两个互相独立的概念：

- **单轮达到本次通过条件**：用户在当前目标上展现出约定程度的回忆能力；
- **跨日保持**：后续在其他时间仍能正确回忆或理解。

不背单词可观察到多阶段训练与同轮再现，**没有可据此复制的内部关卡公式**。

需批准：首次阶段、回忆题型、下一阶段触发条件、连续失败处理、回忆正确后是否提前通过、首次展示答案是否算一次成功、退出是否保留阶段。

### 3.4 D-07：反馈语义与纠错

候选自评文字：
- **认识**：未看答案，能回忆当前被测试的含义；
- **模糊**：有印象但不完整/借助线索，可能并不构成无提示成功；
- **忘记了**：没有回忆或理解错误。

**不要把这三档直接硬映射**成任何成熟算法的原生等级。例如“忘记但点击模糊”可能让长期计划偏离真实能力。

需要明确定义：
- 什么时候可以点击「记错了」；
- 它是撤回最近一次提交、追加修正记录，还是重新作答；
- 已更新下次复习日期时如何更正；
- 两个标签的不同含义是否经真实用户理解测试；
- 网络重试或双端冲突是否会重复推进。

### 3.5 D-10：取消收藏与学习历史

V1.1 已明确：取消收藏时删除该 lemma 的收藏主体与所有关联句子；删除书籍不会删除已收藏快照。

下一版本加入复习后必须决定：
- 取消收藏是否同时永久删除其可辨认学习日志？
- 可否保留不含个人原句的聚合统计？是否允许用户删除全部？
- 仅删除某条收藏原句时，目标义项是否还有其他可靠来源句？
- 一个语境由一个义项调整到另一个义项后，既往复习判定是否仍然有效？

在未批准前，**唯一可确定的外部行为约束是：取消收藏后，不得继续向用户展示依赖该收藏的待复习任务**。历史是否永久删除不得由工程师自行猜测。

### 3.6 D-09：长期调度

PRD 只定义「按结果决定未来复习安排、允许逾期保留、任务负担可控、记录可解释」的行为目标。

任何技术方案还需说明：第一次学习如何冷启动、模糊评分如何映射、纠错如何重算、目标被拆分／合并时如何迁移历史、用户多日不练时如何处理以及是否便于验证。

固定间隔、SM-2、FSRS 的优劣需要可重复的同输入模拟与后续真实记录；不以竞品某轮显示的“1 天／61 天”反推其内部公式。

## 4. 业务验收场景（草案，待各决策批准后成为测试用例）

下表使用 **Given / When / Then**，均以未来复习模块被批准开发为前提。

| ID | Given（前置条件） | When（操作） | Then（期望行为） |
| --- | --- | --- | --- |
| AC-RV-01 | 用户仅点击词典查询，未收藏 | 打开独立复习 | 该词不自动进入待学任务 |
| AC-RV-02 | 用户在一本书收藏 run，另一句收藏 running，lemma 已归并 | 打开收藏与复习 | 收藏主体仅一条；两句仍各可查看，是否一个/多个复习目标取决于义项归组 |
| AC-RV-03 | 用户收藏一个可靠词义且尚未学习 | 启动首次学习 | 能看到需要掌握的可信义项和来源；首次展示答案不被算作独立回忆成功 |
| AC-RV-04 | 多义的 charge 具有“收费”“指控”两条已确认目标 | 回答“指控”的题目 | 不用首次收藏时的“收费”错误判罚合法回答 |
| AC-RV-05 | 同一义项对应三条不同原句 | 一次进入复习 | 可采用某条句子作为材料，但不强制产生三个长期待办 |
| AC-RV-06 | 卡片处于回忆阶段 | 尚未揭示答案 | 目标中文正确答案不可提前可见 |
| AC-RV-07 | 用户反馈“忘记了” | 进入答案页与下一题 | 显示可信纠正解释，并按批准规则保留待加强/重新出现或后续到期 |
| AC-RV-08 | 用户误点“认识”并且符合撤回窗口 | 点击“记错了” | 更正最新有效评价，当前进度与未来计划不继续受错误判断影响 |
| AC-RV-09 | 同一目标因错误再次出现 | 连续练习多次 | 题次数增加，但学习目标数与收藏词数不凭空增加 |
| AC-RV-10 | 某目标在当轮完成 | 查看小结 | 显示当轮通过而非永久学会，并按计划可能在后续再出现 |
| AC-RV-11 | 用户连续数日没有打开产品 | 重新进入复习 | 到期项目仍可处理，不自动将其评分为“忘记了”，可以分批完成 |
| AC-RV-12 | 用户连续失败且本轮达到批准的重复上限 | 继续学习/结束本轮 | 不无限循环，不错误显示已掌握，保留待加强状态 |
| AC-RV-13 | 用户完成若干反馈后退出 | 重新打开复习 | 已成功提交的评价保存，未提交的题目不算完成 |
| AC-RV-14 | 用户反馈提交超时又重试 | 同一逻辑操作重复送达 | 不重复增加完成数、复习次数或多次推进阶段 |
| AC-RV-15 | 用户删除原 EPUB，但保留收藏 | 查看学习卡及来源 | 仍可查看保存的原句、书名、章节快照；原书跳转不可用时不虚构链接 |
| AC-RV-16 | 用户取消收藏一整个 lemma | 重新打开学习与任务队列 | 对应目标不再出现；后续历史处理遵从批准的 D-10 策略 |
| AC-RV-17 | 一条原句没有可靠的目标义项 | 尝试将其用于准确评分题 | 系统不以未经确认的默认词义强判，应提示需确认或不进入该题 |
| AC-RV-18 | 用户 A 与用户 B 各自收藏相同 lemma | 读取复习任务 | 只能看到自己的语境、进度、反馈和安排 |

**注意：** AC-RV-03/04/05/08/12/16/17 的操作细节需先完成 D-01、D-02、D-03、D-05、D-06、D-07、D-10。未决条件不得在验收时由测试人员自行选定。

## 5. 最小验证方案：评审应看见什么证据

| 决策组 | 最少可行验证材料 | 是否需要真人 |
| --- | --- | --- |
| D-01 + D-05 多义目标与释义 | 10～20 条覆盖同义多句、不同义项、词形归并的真实语境；检查词义来源与不确定情形 | 建议有语言能力的人工核验 |
| D-02 + D-03 + D-04 学习流程 | 固定多阶段和动态多阶段的可点击原型；首次、认识、模糊、忘记、退出 5 条操作路径 | 至少做少量目标用户任务观察 |
| D-06 + D-08 负担 | 不同批次长度、错误比例和重复上限下的操作时长；积压流程演示 | 建议真人试用 |
| D-07 纠错 | 误判、撤回、重试、跨会话恢复的状态表和测试用例 | 工程测试＋可用性观察 |
| D-09 调度 | 相同反馈序列下的算法模拟；测试一周未练和学习目标拆分 | 初期可离线模拟，真实收益需后续验证 |
| D-10 删除与改义 | 取消收藏、删句、删书、重归义项对历史的影响测试 | 产品决策＋工程验证 |
