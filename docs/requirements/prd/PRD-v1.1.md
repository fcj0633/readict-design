# 一、产品定位与目标

## 1.1 产品定位

面向具有一定英语基础、通过英语原版书籍提升阅读能力的用户，提供集电子书阅读、本地英汉词典查询、原文语境关联和收藏管理于一体的辅助学习工具。

本产品不以替代专业电子书阅读器为目标，而是希望在提供舒适阅读体验的基础上，降低用户阅读时查询单词和积累词汇的成本。

## 1.2 核心问题

当前用户使用阅读器和词典软件时，主要存在以下问题：

1. 阅读与查词相互分离，查询单词需要切换软件。
2. 词典虽然能够提供标准释义，但难以直接体现单词在当前阅读内容中的用法。
3. 收藏单词通常缺少真实原文例句，后续回看时容易脱离语境。
4. 部分阅读学习软件将大量工具和信息堆积在阅读界面，影响阅读体验。
5. 查询结果可能包含大量词义，用户需要自行筛选，增加理解成本。

## 1.3 核心价值

**让用户在不离开原文阅读场景的情况下，快速理解单词，并将值得保留的单词与真实原文语境一起收藏，方便后续查阅和积累。**

核心业务闭环：

导入书籍 → 阅读原文 → 点击查词 → 理解词义 → 收藏单词及其原文句子 → 在收藏中回看和管理。

## 1.4 产品设计原则

| 原则 | 具体要求 |
|---|---|
| 阅读优先 | 尽量减少工具对阅读区域的占用 |
| 简洁 | 常用功能入口少而明确 |
| 查词快速 | 常规查词不依赖 AI 生成 |
| 词典可靠 | 基础词义来自标准词典 |
| 语境保留 | 默认展示真实原文，而非脱离场景的例句 |
| 低干扰 | 查询卡片浮动显示，不重排正文 |
| 用户自主 | 只有用户主动收藏，单词及其原文语境才进入收藏 |
| 数据可靠 | 书籍、收藏内容、阅读进度和个人设置持久化 |

# 四、阅读器功能需求

## 4.1 书架与书籍管理

### 功能目标

用户能够上传 EPUB 文件，建立个人书架并进入阅读。

### 书架页面

每本书以卡片形式展示：

- 封面。
- 书名。
- 作者。
- 阅读进度。
- 最近阅读时间。

主要操作：

- 上传 EPUB。
- 打开书籍。
- 删除书籍。
- 搜索书籍。

### EPUB 导入流程

1. 用户选择本地 EPUB 文件。
2. 前端检查文件格式和文件大小。
3. 上传至服务端。
4. 服务端解析 EPUB 元数据。
5. 解析目录和正文。
6. 保存原始 EPUB 和解析资源。
7. 建立书籍记录。
8. 导入成功后显示在书架。

### 格式要求

支持：

- 普通 EPUB 2。
- 常见 EPUB 3 可重排版内容。
- 英文 XHTML 正文。
- 常见图片与 CSS 资源。

暂不支持 DRM 加密书籍和固定版式 EPUB。

### 删除规则

删除书籍时：

- 删除原始文件和书籍资源。
- 删除阅读进度或标记其不可恢复。
- 保留已经收藏的单词。
- 保留收藏的原文例句和词典释义。
- 收藏记录仍然可以在收藏页面查看。

---

## 4.2 阅读器主界面

### A. 顶部区域

展示：

- 返回书架。
- 当前书籍名称。
- 目录入口。
- 基础阅读设置入口。

不需要在顶部展示大量按钮和文字说明。

### B. 阅读内容区域

采用单页分页模式。

页面展示：

- 当前章节名称。
- 当前页码。
- 当前章节页数。
- 正文内容。

分页信息属于阅读画布的一部分，不单独建立复杂的底部导航区。

### C. 右侧功能栏

采用独立的竖向单按钮排列。

第一版建议三个入口：

| 功能 | 说明 |
|---|---|
| 章节目录 | 展开目录，切换章节 |
| 收藏 | 查看和管理已收藏的单词及原文句子 |
| 阅读设置 | 调整字体和阅读样式 |

图标使用简洁的单色图标。

每个按钮独立，悬停时展示简短说明。

点击按钮后按需打开对应功能区域，不需要同时展示全部侧栏。

### D. 正文宽度

正文不能随着屏幕宽度无限扩大。

建议：

- 主阅读内容区域保持居中。
- 使用最大正文宽度限制。
- 默认正文宽度以约 620～720px 为设计起点。
- 英文文本行宽建议控制在约 60～70 个字符。
- 屏幕空间不足时自适应缩小。
- 在宽屏下保留适当留白。

上述尺寸为初始设计参考，需要经过实际页面测试确定。

## 4.3 阅读样式

第一版只提供必要设置。

| 设置 | 可选值 |
|---|---|
| 字体大小 | 小、中、大、特大 |
| 字体类型 | 2～3 种适合英文阅读的字体 |
| 行间距 | 紧凑、标准、宽松 |
| 正文宽度 | 标准、宽松 |
| 背景颜色 | 白色、暖色、深色 |

用户修改设置后自动保存。

不同书籍默认共用用户的阅读偏好，暂不设计复杂的单本书个性化主题。

## 4.4 分页与阅读进度

### 分页要求

- 一次展示一个阅读页面。
- 能够上一页、下一页。
- 支持键盘左右方向键。
- 提供轻量的页面切换入口。
- 切换页面不应该造成正文重复或丢失。
- 页面尺寸变化时重新计算分页。

### 阅读位置保存

不能只保存页码。

建议保存：

- 当前书籍 ID。
- 当前章节 ID。
- EPUB CFI 或稳定内容定位标识。
- 当前阅读进度。
- 最近阅读时间。

重新进入书籍时，尽可能恢复到上一次阅读的准确位置。

# 五、单词点击与浮动词典卡片

## 5.1 功能目标

用户点击正文中的英文单词时，在该单词附近显示一个浮动查询卡片。

浮动卡片是第一版最重要的交互设计。

设计参考为用户提供的微读查询卡片截图。

核心要求：

**查询卡片跟随被点击的单词定位，作为临时浮层出现在阅读区域中，不占据常驻页面空间，也不改变原文的分页和排版。**

## 5.2 浮动卡片的定位

卡片采用锚定弹出方式。

交互规则：

1. 用户点击单词。
2. 获取单词在阅读器中的屏幕坐标。
3. 以该单词作为浮动卡片的定位锚点。
4. 优先在单词右侧显示。
5. 右侧空间不足时显示在左侧。
6. 垂直空间不足时自动调整卡片上下位置。
7. 卡片不允许超出浏览器可视区域。
8. 通过小三角或指向箭头关联被点击单词。

不要使用全屏遮罩。

不要因为打开卡片而重新计算正文宽度。

不要让卡片把用户正在阅读的单词完全遮挡。

如果附近无法放置卡片，可以向阅读区域更宽裕的位置移动，但必须保留明确的指向关系。

## 5.3 卡片的基本结构

卡片参考上传的截图，采用以下布局：

### 第一部分：查询标题栏

- 标题：查询。
- 关闭按钮。

### 第二部分：词典信息区域

展示：

- 单词原型。
- 发音按钮（接口与状态预留；音频待文件分析，未就绪时明确提示不可用，不假装可播放）。
- 原文词形。
- 音标。
- 当前词性。
- 主要中文释义。
- 词典来源。

示例：

**running**

/ˈrʌnɪŋ/

原型：run

verb

跑；奔跑

词典来源：具体采用的词典供应商。

### 第三部分：其他释义

默认折叠。

例如：

其他释义（3）

点击后才展示其他词性、其他含义。

第一版优先展示最符合当前句子词性的释义，不允许把完整词典词义无序堆积在卡片中。

### 第四部分：原文语境

展示：

- 当前单词所在的完整英文句子。
- 点击的目标单词进行高亮。
- 所属书籍及章节。

默认展示原文，不显示翻译。

### 第五部分：操作区域

主要操作：

- 收藏单词及当前原文句子。
- 翻译例句。

收藏应该容易找到，不应该被折叠。

翻译是一个独立操作，用户不点击时不自动执行。

## 5.4 卡片尺寸

卡片不应无限增高。

建议设计参考：

| 属性 | 初始设计目标 |
|---|---|
| 桌面端宽度 | 360～440px |
| 最大高度 | 可视区域的 70%～80% |
| 圆角 | 适度圆角 |
| 背景 | 浅色或适配主题的纯色背景 |
| 阴影 | 轻量阴影 |
| 内容布局 | 分区清晰，信息紧凑 |
| 超出高度 | 卡片内部滚动 |

截图中的大卡片可以作为视觉参考，但不需要无条件复制其全部留白。

词典信息不多时，卡片应该自然收缩。

## 5.5 卡片的生命周期

- 点击单词：打开卡片。
- 点击其他单词：卡片更新，锚点移动。
- 点击关闭：关闭卡片。
- 按 Escape：关闭卡片。
- 点击阅读区域其他空白处：关闭卡片。
- 切换章节或翻页：关闭当前卡片。
- 调整窗口大小：重新计算卡片位置。
- 点击收藏：卡片保留，并更新收藏状态。

在词典请求过程中，切换到另一个单词时，应当取消不必要的旧请求，或者忽略旧请求的迟到结果，避免显示错误的单词信息。

# 六、词典功能设计

## 6.1 数据来源

第一版的单词基础翻译必须来自标准英语词典。

不通过大模型直接生成基础词典释义。

首版本地 COL 数据需尽可能覆盖以下信息，来源、版本和可用性明确标注：

- 单词原型。
- 音标。
- 发音资源（待用户后续提供文件再分析，不作为本轮文字词典验收条件）。
- 词性。
- 中文释义。
- 多个词义及其顺序。
- 数据来源标识。

实际接入前需要验证接口能力、词汇覆盖率和商业使用许可。

## 6.2 原文词形与单词原型

例如：

| 原文词形 | 词典原型 |
|---|---|
| running | run |
| books | book |
| played | play |
| studies | study |
| children | child |

系统同时保存原始词形和标准原型。

不能仅保存原型，否则会丢失用户真实遇到的原文形式。

## 6.3 当前句子的词性识别

这是第一版词义选择的关键逻辑。

用户点击单词时，系统需要：

1. 提取单词原始形式。
2. 获取所在的完整英文句子。
3. 进行词形还原。
4. 从词典获取词条和多个词义。
5. 识别当前单词在句子中所处的词性。
6. 在词典结果中优先选择相同词性的释义。
7. 如果存在多个相同词性的释义，优先选择词典排序靠前的常用释义。
8. 其他释义默认折叠。

例如：

run：

- 作为动词：跑步、经营、运行。
- 作为名词：奔跑、行程。

用户在句子 `She runs a business.` 中点击 runs。

系统应该优先选择动词释义，并优先考虑与该用法相关的常见解释，而不是默认展示名词释义。

需要区分两个层次：

- 词性识别：当前是名词还是动词。
- 具体词义判断：当前是跑步、经营还是运行。

第一版主要解决第一层，第二层主要依靠词典的释义顺序，暂时不保证对所有多义词都能精准完成语义消歧。

对于无法确定词性的情况，回退到词典默认排序，并允许展开其他含义。

不能在识别不确定时强行给出确定的语境解释。

## 6.4 查询过程

建议采用异步并行处理：

**词典处理链路：**

点击单词 → 词形还原 → 查询词典缓存 → 查询版本化本地 COL 数据集 → 词义排序 → 返回结果。

**原文处理链路：**

点击单词 → 获取所在句子 → 获取书籍和章节 → 获取原文位置 → 返回上下文。

两条链路相互独立。

词典查询失败不影响原文展示。

原文定位失败也不应该阻止词典查询。

## 6.5 多义词展示规则

默认只展示一个主要释义。

其他含义折叠。

用户点击其他释义入口后，展示：

- 其他词性。
- 对应释义。
- 词典释义顺序。

如果用户发现当前展示的释义不符合实际语境，可以在查询卡片中展开其他释义并切换当前展示。

当前版本的收藏主体按单词原型归并，不按词性或词义拆分。切换释义只影响当前查询展示；收藏同一单词时仍然进入同一个收藏主体，不会因为选择了不同词义而创建新的收藏项。收藏记录可以保存首次收藏时展示的主要释义快照，但不提供同一单词的多义收藏管理。

## 6.6 词典缓存

相同词典原型不应该重复请求外部服务。

建议建立词典缓存：

- 按单词原型缓存。
- 缓存完整词条。
- 缓存多个词义。
- 缓存音标；发音资源的存储和缓存方案待音频文件分析后决定。
- 记录数据来源。
- 根据供应商规则设置更新周期。

用户查询时优先读取缓存。

# 七、原文上下文和例句翻译

## 7.1 原文上下文

用户点击单词后，系统默认展示当前单词所在的完整句子。

例如：

原文：

The old man was thin and gaunt with deep wrinkles in the back of his neck.

其中 gaunt 高亮。

同时展示：

- 书籍名称。
- 章节名称。
- 原文定位信息。

上下文直接来源于 EPUB 解析结果，不是 AI 生成内容。

## 7.2 默认不自动翻译

用户点击单词后不自动调用句子翻译服务。

原因：

- 查词属于高频操作。
- 整句翻译属于相对低频操作。
- 同一个句子可能被多次查询。
- 自动翻译会产生不必要的服务请求。
- 会增加浮动卡片的复杂度。

## 7.3 用户主动翻译

原文下方设置一个按钮：

**翻译例句**

用户点击后：

1. 展示加载状态。
2. 向翻译服务发送原文句子。
3. 使用当前句子的上下文辅助翻译。
4. 接收翻译结果。
5. 在原文下方显示中文翻译。
6. 保留原文，不替换原文内容。

翻译完成后的展示：

原文：

The old man was thin and gaunt with deep wrinkles.

翻译：

老人身形消瘦，面容憔悴，颈后有着深深的皱纹。

上述内容仅为界面示例，实际翻译以翻译服务返回结果为准。

### 翻译规则

- 只翻译当前完整句子。
- 不翻译整页或整章。
- 不自动生成语法分析。
- 不自动将翻译结果加入收藏。
- 用户再次打开卡片时，可以重新展示已获取的翻译。
- 翻译失败时提示重试，不影响词典卡片。

可以建立翻译缓存，避免重复请求相同句子。

## 7.4 翻译服务的数据要求

翻译接口应独立于词典接口。

输入：

- 当前原文句子。
- 必要的相邻上下文。
- 目标语言：中文。

输出：

- 原文句子。
- 中文翻译。
- 服务来源。
- 请求状态。

当前技术方向已按用户确认选择腾讯云 TMT；产品只要求用户主动请求原句翻译，不绑定生成式 AI。SDK、凭据、额度和真实调用及条款仍须验证，详见 ADR-0001。

# 八、收藏功能

## 8.1 收藏目标

用户在浮动词典卡片中主动点击收藏，将当前查询的单词和它在原文中的句子一起保存，方便后续集中查看。

收藏是一个以单词为主体、以原文句子为关联内容的管理体系。

## 8.2 收藏主体与唯一性

当前版本采用以下规则：

1. 同一用户的同一个单词原型（lemma）只建立一个收藏主体。
2. 单词收藏的唯一性不区分词性和词义。
3. 不支持同一个单词按不同词义创建多个收藏项。
4. 单词的不同词形，例如 run、runs、running，在词形还原结果一致时归入同一个收藏主体。
5. 如果词形还原失败，则使用规范化后的原始词形作为回退标识，避免收藏操作失败。
6. 同一单词再次出现在其他书籍、章节或句子中时，向已有收藏主体追加新的原文句子，不重复创建单词收藏。
7. 同一个收藏主体下的相同原文句子需要去重。

例如：用户先在 `He runs every morning.` 中收藏 runs，之后又在 `She runs a business.` 中收藏 runs。系统仍然只保留一个 `run` 收藏主体，并将两条原文句子关联到该主体。

## 8.3 收藏内容

单词收藏主体保存：

- 单词原型（lemma）。
- 首次收藏时遇到的原文词形。
- 音标（词典可提供时）。
- 首次收藏时的主要词性和释义快照。
- 收藏时间。

每条关联原文句子保存：

- 完整英文原文句子。
- 当前点击单词在句子中的高亮位置或字符范围。
- 当前出现的原文词形。
- 例句翻译（如果已经完成）。
- 书籍名称快照。
- 章节名称快照。
- 原文定位信息（如 EPUB CFI）。
- 句子收藏/关联时间。

不同原文句子作为独立关联记录保存，不能因为单词原型相同而相互覆盖。

当前版本不维护同一个单词的多套词义收藏。后续查询到不同词性的释义时，不新建收藏主体，也不自动覆盖首次收藏时保存的主要释义快照。

## 8.4 收藏操作规则

用户点击收藏后：

1. 根据当前单词的 lemma 生成收藏主体唯一标识。
2. 查询当前用户是否已经收藏该单词。
3. 如果尚未收藏，创建单词收藏主体。
4. 如果已经收藏，复用已有主体。
5. 将当前原文句子作为关联语境保存；若该句子已存在则不重复插入。
6. 返回收藏主体及当前句子的收藏状态。

操作入口状态：首次收藏时显示“收藏”；单词已收藏但当前句子尚未收藏时显示“收藏本句”；单词和当前句子均已收藏时显示“已收藏”。

收藏成功后：

- 收藏按钮状态改变。
- 显示轻量成功提示。
- 不关闭浮动卡片。
- 允许继续查询其他单词。
- 已收藏单词再次查询时，如果当前句子尚未收藏，操作入口显示“收藏本句”；点击后只追加该句子，不重复创建单词收藏主体。如果当前句子也已收藏，则显示“已收藏”。

取消收藏时，删除该单词收藏主体及其关联的收藏句子。公共词典数据、书籍原始文件和查询记录不受影响。取消收藏的具体二次确认交互由界面设计确定。

## 8.5 书籍删除与收藏数据

删除书籍时，已收藏的单词和原文句子必须保留。关联句子保存书名、章节名和原文内容快照；书籍删除后，原书关联 ID 可以置空或标记为已删除，但不能影响收藏内容查看。

# 九、收藏页面

## 9.1 页面目标

收藏页面集中展示用户主动保存的单词及其关联原文句子，不承担复习任务管理。

## 9.2 页面结构

收藏页面提供两种查看方式：

- **单词视图：** 按单词原型展示收藏主体，每个单词只出现一次，并显示关联句子数量、音标及主要释义。
- **句子视图：** 展示已收藏的原文句子，每条句子标明所属单词、书籍和章节；同一单词可以对应多条句子。

句子是单词收藏主体下的语境内容。当前版本不支持脱离单词、单独创建句子收藏。

## 9.3 列表功能

支持：

- 按单词原型或原文句子内容搜索。
- 按来源书籍筛选。
- 按收藏时间排序。
- 切换单词视图和句子视图。
- 查看单词详情及其关联的全部原文句子。
- 删除单词收藏。

当前版本不展示复习状态、待复习时间或学习进度。

## 9.4 收藏详情

单词详情显示：

- 单词原型。
- 音标（如有）。
- 首次收藏时保存的主要词性和释义。
- 关联的多条原文句子。
- 每条句子的翻译（如已获取）。
- 每条句子的来源书籍及章节。
- 收藏时间。

当前版本不提供同一个单词的多义收藏管理，也不提供复习入口。

# 十、复习功能（后续版本）

复习功能不属于当前版本 P0 范围，当前版本不实现复习页面、复习队列、间隔重复算法、复习计划或复习历史。

当前版本只完成单词收藏和原文语境保存。收藏数据结构应保留后续扩展能力，未来可以在单词收藏主体上增加复习计划和复习记录，而不需要改变当前收藏主体与原文句子的基本关系。

复习功能后续版本可考虑：

- 原文填空式复习。
- 显示单词原型、音标、释义和原文句子。
- 忘记、模糊、认识、熟悉等复习评价。
- 根据评价调整下一次复习时间。
- 今日待复习数量和复习历史。

上述内容仅作为后续方向，不属于当前版本验收范围。

# 十一、个人设置

第一版只需要简单的个人设置。

## 11.1 账号设置

### 注册与登录方式

- 用户可以使用手机号注册，也可以使用邮箱注册。
- 用户可以使用已注册的手机号或邮箱作为登录账号。
- 登录时使用手机号或邮箱加密码进行身份验证。
- 手机号和邮箱作为账号标识，分别保证唯一性。
- 当前版本不要求同一账号必须同时绑定手机号和邮箱。

手机号或邮箱的注册验证方式（短信验证码或邮箱验证码）及具体服务供应商需要在技术设计阶段确定。

### 密码规则

- 密码长度不少于 8 位。
- 必须同时包含至少一个数字（0–9）和一个英文字母（A–Z 或 a–z），不要求同时包含大小写。
- 允许额外特殊符号，但不强制要求；不限制为只能输入数字和字母。
- 注册、修改密码和重置密码时均需要执行相同的密码规则校验。

### 账号操作

- 查看当前登录账号（手机号或邮箱）。
- 修改密码。
- 退出登录。
- 忘记密码及密码重置流程需要支持，具体验证方式沿用手机号或邮箱验证机制。

## 11.2 阅读设置

- 字号。
- 字体。
- 行间距。
- 正文宽度。
- 背景主题。

## 11.3 词典设置

- 英式发音优先。
- 美式发音优先。

设置保存到数据库，用户重新登录后仍然生效。

# 十二、核心数据设计要求

第一版数据库围绕用户、书籍、词典、翻译和收藏五个领域设计，不建设复习业务数据表。

## 12.1 用户与设置

- User：用户信息，包含手机号或邮箱登录标识、密码哈希和账号状态。
- UserSettings：个人偏好。

手机号和邮箱分别建立唯一约束；用户至少具有一个登录标识。密码只保存经过安全哈希处理的结果，不保存明文密码。

## 12.2 书籍与阅读

- Book：书籍信息。
- BookChapter：章节信息。
- ReadingProgress：阅读位置。

## 12.3 词典数据

- DictionaryEntry：标准词典词条。
- DictionarySense：词典词义。

词典数据属于公共缓存，与用户收藏数据分离。查询时可以展示多个词义，但收藏不按词义拆分。

## 12.4 原文语境与翻译

- SentenceTranslation：用户请求过的原文句子翻译缓存。
- FavoriteWordContext：单词收藏主体关联的原文句子。

当前版本不要求为 EPUB 中每个单词预先建立 WordOccurrence 全量记录。用户查词时可从当前阅读 DOM 提取原文语境，在收藏时保存被用户选择的句子和定位信息。

## 12.5 用户收藏数据

- LookupHistory：查询记录（如产品需要保留查询历史）。
- UserFavoriteWord：用户收藏的单词主体。
- FavoriteWordContext：单词收藏主体关联的原文句子。

## 12.6 核心关系与约束

1. 词典词条属于公共词典数据，不直接绑定单一用户。
2. 收藏记录属于具体用户。
3. `UserFavoriteWord` 按 `(user_id, normalized_lemma)` 建立唯一约束；同一用户的同一单词原型只能有一个收藏主体。
4. 收藏唯一性不区分词性和词义，当前版本不支持同一个单词按不同词义建立多个收藏项。
5. 一个单词收藏主体可以关联多条原文句子。
6. 同一单词在不同书籍或章节中再次出现时，追加语境记录，不创建新的收藏主体。
7. `FavoriteWordContext` 保存原文句子、目标单词词形、书名快照、章节快照和 EPUB 定位信息。
8. 原文句子需要具备稳定的去重标识，避免同一收藏主体重复保存相同语境。
9. 删除书籍不能导致已收藏的单词和原文句子快照丢失。书籍关联可置空或标记删除，但收藏快照继续保留。
10. 当前版本不创建 ReviewSchedule、ReviewLog 等复习业务表；后续复习功能可以关联 `UserFavoriteWord` 扩展。

## 12.7 存储方式

关系型数据库保存：

- 用户与个人设置。
- 书籍元数据和章节信息。
- 阅读进度。
- 词典缓存。
- 句子翻译缓存。
- 查询记录（如启用）。
- 单词收藏主体及其关联原文句子。

文件或对象存储保存：

- 原始 EPUB。
- 封面。
- EPUB 图片。
- 解析后的章节资源（如服务端解析流程需要）。

数据库保存文件和资源的引用。

所有用户数据需要按照登录身份进行权限隔离。

# 十三、关键性能和异常处理

## 13.1 性能目标

| 操作 | 目标 |
|---|---|
| 书架加载 | 正常网络下流畅展示 |
| 阅读翻页 | 无明显卡顿 |
| 页面恢复 | 能够恢复到上次阅读位置 |
| 查词 | 常见词汇首屏结果 P95 目标不超过 1 秒 |
| 词典缓存 | 相同词条尽量避免重复请求 |
| 浮动卡片 | 出现和关闭不影响正文分页 |
| 例句翻译 | 异步处理，不能阻塞基本查词 |
| 收藏 | 收藏主体和关联句子保存成功后及时反馈 |

性能目标需要通过真实词典接口、翻译服务和设备测试验证。

## 13.2 异常情况

| 异常 | 处理方式 |
|---|---|
| EPUB 解析失败 | 显示失败原因，允许重新导入 |
| EPUB 不兼容 | 明确提示暂不支持 |
| 词典没有结果 | 展示未找到词条，保留原文 |
| 词形还原失败 | 尝试直接查询原始词形 |
| 词性无法识别 | 回退至词典默认排序 |
| 词典查询超时 | 提供重试，不影响阅读 |
| 上下文提取失败 | 仍然展示词典释义 |
| 例句翻译失败 | 展示原文并允许重新翻译 |
| 收藏失败 | 不显示虚假收藏成功状态 |
| 阅读进度保存失败 | 提示用户并重试 |
| 登录过期 | 提示重新登录 |
| 手机号或邮箱验证失败 | 提示验证失败并允许重新获取验证码 |
| 密码不符合规则 | 提示“密码不少于 8 位，且至少包含一个数字和一个英文字母” |
| 同一单词重复收藏 | 复用已有单词收藏主体，并追加尚未保存的原文句子 |
| 删除书籍 | 不删除已有收藏资料 |

# 十四、第一版验收标准

## 14.1 阅读器验收

- 用户能够成功导入普通 EPUB。
- 能够正确展示书名、章节和正文。
- 支持单页分页阅读。
- 正文具有合理的最大宽度。
- 支持调整字体大小和阅读样式。
- 目录跳转正确。
- 能够正常上一页和下一页。
- 退出重新进入后，能够恢复阅读位置。
- 右侧功能栏各入口正常工作。

## 14.2 浮动卡片验收

- 点击单词后，卡片出现在单词附近。
- 卡片具有明确的指向关系。
- 卡片不会超出浏览器窗口。
- 空间不足时能够调整位置。
- 打开卡片不改变正文分页。
- 点击其他单词时卡片能够正确更新。
- 关闭卡片后可以继续阅读。
- 卡片加载失败不会影响正文。

## 14.3 词典验收

- 能够识别原文单词。
- 能够进行常见词形还原。
- 能够展示词典原型。
- 能够展示音标和词性。
- 发音能力保留为后续验收项：待补充音频文件并完成分析后，验证有可用音频时能够正常播放；本轮阶段验收不包含真实录音播放。
- 能够根据当前句子词性优先选择释义。
- 其他含义默认折叠。
- 无法确定词性时能够合理回退。
- 词典数据来源可追溯。

## 14.4 语境和翻译验收

- 点击单词后默认展示所在的原文句子。
- 目标单词在例句中高亮。
- 展示书名和章节。
- 不自动请求整句翻译。
- 用户点击翻译后异步获取中文结果。
- 翻译加载期间仍可查看词典信息。
- 翻译失败不影响查询和收藏。
- 翻译完成后不替换原文。

## 14.5 收藏验收

- 用户能够从浮动词典卡片一键收藏单词及当前原文句子。
- 同一用户对同一 lemma 只能存在一个收藏主体。
- 同一单词以不同词形出现时，能够归并到同一个收藏主体。
- 同一单词在不同句子或书籍中再次出现时，能够追加关联原文句子。
- 同一收藏主体下相同的原文句子不会重复保存。
- 收藏主体能够查看关联的多条原文句子。
- 收藏页面支持单词视图和句子视图。
- 收藏记录保存原文词形、句子、书籍/章节快照及定位信息。
- 删除书籍后，已收藏的单词和句子仍然可以查看。
- 取消收藏后，单词收藏主体及关联句子按规则删除，不影响公共词典数据。
- 当前版本不支持同一单词按不同词义建立多个收藏项。

## 14.6 用户账号验收

- 用户能够使用手机号或邮箱注册。
- 用户能够使用已注册手机号或邮箱加密码登录。
- 手机号和邮箱分别保证唯一性。
- 密码不少于 8 位，且至少包含一个数字和一个英文字母。
- 注册、修改密码和重置密码时均执行相同密码规则校验。
- 用户能够修改密码并退出登录。
- 用户数据按登录身份隔离。

# 十五、第一版开发阶段

## 阶段一：项目基础和用户系统

- Web 项目基础结构。
- 手机号或邮箱注册、登录。
- 密码规则校验。
- 修改密码、退出登录及密码重置基础流程。

验收：用户能够通过手机号或邮箱注册、登录；密码规则生效；个人设置能够持久化。

- EPUB 上传。
- EPUB 解析与安全检查。
- 书架。
- 分页阅读。
- 目录。
- 阅读样式。
- 阅读位置保存。
- 右侧功能栏及收藏入口。

验收：用户能够导入英文 EPUB，完成基本阅读并恢复阅读位置。

## 阶段三：浮动查词与词典

- 词典数据源接入。
- 词形还原。
- 词性识别。
- 词典缓存。
- 单词点击。
- 浮动卡片。
- 当前句子提取。
- 主要释义选择。
- 其他释义折叠。

验收：用户能够在阅读过程中点击单词，获取词典信息和当前原文语境。

## 阶段四：例句翻译与收藏

- 主动翻译。
- 翻译缓存。
- 单词收藏主体。
- 同一 lemma 收藏归并。
- 同一单词多条原文句子关联。
- 收藏页面的单词视图和句子视图。
- 收藏搜索、筛选和详情。
- 书籍删除后的收藏快照保留。

验收：用户能够查询单词、翻译当前例句、收藏单词及其原文句子，并在收藏页面查看和管理。

## 阶段五：体验优化与质量保障

- 浮动卡片定位优化。
- 阅读排版优化。
- 词典查询性能优化。
- EPUB 兼容测试。
- 浏览器兼容测试。
- 数据安全和异常测试。
- 收藏去重、并发收藏和书籍删除场景测试。

验收：核心阅读、查词、翻译和收藏流程稳定，关键异常得到合理处理。

## 后续版本：复习功能

复习功能不纳入当前版本开发和验收。后续版本可在现有单词收藏主体上增加复习队列、间隔重复算法、复习评价、复习计划和复习历史。

# 十七、第一版产品定义总结

第一版不是要实现一个功能繁多的英语学习平台，而是先构建一款舒适、简单、实用的原版书阅读与语境收藏工具。

它需要具备两个最重要的特点：

**第一：阅读体验。**

- 阅读区域适中。
- 排版简洁。
- 功能入口少而清晰。
- 分页自然。
- 不被常驻学习面板打扰。

**第二：即时理解和词汇积累。**

- 点击单词即可查询。
- 浮动卡片显示词典信息。
- 按照当前句子的词性优先选择释义。
- 默认展示真实原文例句。
- 用户主动翻译例句。
- 一键收藏单词及其原文句子。
- 在收藏页面集中查看单词和相关句子。

最终形成：

**阅读 → 查词 → 理解 → 收藏单词与原文句子 → 回看和管理收藏 → 再次阅读。**

这是第一版需要重点打磨的核心产品链路。
