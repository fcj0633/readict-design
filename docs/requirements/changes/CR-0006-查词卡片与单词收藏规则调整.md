## 1. 背景与目标

当前正式工程已具备真实 EPUB 阅读、COL 词典查询、真人录音播放接口、单词收藏与原文语境持久化，以及统一的账号、书架、收藏页面。UX-U03 已完成主要本机自动验证，最终人工视觉确认及未覆盖项仍待完成。

本次用户实际使用后的反馈主要是：
- 词典释义展示不符合期待的词典分组；词形与词头存在重复信息。
- 展开释义时浮层向上跳动，影响阅读连续性；关闭动作不够自然。
- 收藏操作包含额外确认、成功提示和当前语境状态，操作成本高。
- 收藏列表行高和留白较大，缺少直接播放录音及完整释义详情；当前句子视图、语境追加与原文跳转并非本阶段需要的能力。
- 手机号应作为认证默认方式。

目标：降低阅读时查词和收藏的操作成本；保持真实词典数据及用户原文例句的价值；让收藏成为易于浏览的单词列表；明确未来独立句子收藏与单词例句的不同生命周期，并精简不再需要的收藏定位数据。

## 3. 查词卡片

### 3.1 CR6-D01 释义分组

**原行为：** 目前卡片取当前 region 的 senses，默认前三条，其余折叠；前端使用归一化词性 pos，未显式保留 rawPos；同一 lemma 的多个 region 可能未完整展示。

**目标行为：** 以词典原生释义结构为展示单位。一个释义组可以包含多个中文同义释义。不得根据中文逗号、分号随意拆分，也不得将词性相同但语义独立的组粗暴合并。保留词典词性标注、分组边界和原始组内顺序。

示例（用户提供的展示规则，非实际词典数据验证结果）：

~~~text
accept
vt. 接受;领受;收受
vt. 承认;认可;同意,答应
vt. 承担;担任(职位)
~~~

规则：
1. 如词典原始标签为 vt.、vi.、n. 等，按真实标签展示。若仅有通用 verb 等归一化值，不臆造及物/不及物属性。
2. 同一词典原型下的多个有效 region 按词典结构组织；不同原型、不同候选词条不得误并。保持现有歧义候选切换能力，不把词头隐藏等同于取消候选识别。
3. 卡片默认展示至多前三个释义组（沿用既有主要释义及两个其他释义的数量边界），不足三组则全部展示；超过三组显示“更多释义”。若存在可信的既有词性优先信息，仍按原有规则确定主要释义，其他组保留词典顺序；不引入新 AI 语境消歧或人为编造“当前词义”。
4. 释义、音标、原文语境仍保持明确的视觉层级；不增加词典额外例句，当前阅读原句仍独立展示。
5. 解析质量不足时，不通过分号强制重组或生成假释义；以真实原始信息降级，记录不能还原的条目。正式技术设计先核对已导入 COL 数据和解析证据，再判断是否需要增量解析或重新导入。不得因一个示例就宣布整个词典质量已达标。

### 3.2 CR6-D02 原型与词形

卡片标题展示已确认词典原型；无法确定原型时使用实际点击的词面，并保留现有未知或歧义提示。音标仅显示真实可用值。

| 原文词形 | 已确定原型 | 标题 | 原文词形行 |
| --- | --- | --- | --- |
| accept | accept | accept | 不显示 |
| Accept | accept | accept | 不显示（仅句首大小写差异） |
| accepted | accept | accept | 显示 accepted |
| went | go | go | 显示 went |
| 未命中/无法确认 | 无 | 实际原文词形 | 不重复显示 |

移除独立的“词头：xxx”展示及重复的技术性 lemmaKey 文案；真实词条候选选择不受影响。headword、lemma、lemmaKey、原始词面等内部数据不因此删除。大小写处理使用现有词典归一化规则，不合并真实不同的词条。

### 3.3 CR6-D03 稳定展开和滚动

- 首次查词完成时按单词锚点和可用视口确定位置；加载态到真实结果允许完成初始定位。位置应给出足够可阅读高度，不贴底留下不可用的狭窄区域。
- 用户点击更多释义后，已显示内容、卡片左上角位置保持稳定；新增释义自然向下展开，不能因高度增加把卡片整体向上推移或重新水平定位。
- 超出可用空间时内部滚动，浮层始终在可用视口中，不扩大正文、滚动整页或破坏 EPUB 分页。收起时同样保持卡片位置。
- 滚动和点击“更多/收起”不应触发关闭、重新查询或音频播放中断。避免展开造成滚动位置意外跳回顶部；折叠后焦点仍可访问。
- 切换另一单词、翻页、视口大小变化仍允许按现有阅读器逻辑重新定位或关闭。
- 在桌面靠上、居中、靠底位置和窄屏验证；键盘可操作展开按钮与滚动区域。不要求固定像素高度，以用户可正常阅读且不跳动为标准。

### 3.4 CR6-D04 卡片关闭

| 操作 | 预期 |
| --- | --- |
| 点击阅读纸面、父页面其他空白处 | 关闭当前卡片 |
| 点击 EPUB iframe 内的非单词区域 | 关闭当前卡片 |
| 点击其他有效单词 | 替换旧卡片并查新词 |
| 点击卡片内部、展开、发音、收藏、滚动 | 不关闭 |
| 正文拖选或与原有可交互元素交互 | 不误触发查词，不破坏原交互 |
| 点击关闭 X、按 Esc | 保留辅助关闭方式 |
| 翻页/离开阅读页 | 继续按既有生命周期关闭 |

关闭时停止本卡片录音并取消/失效未完成查词；清理本卡片高亮。连续点击、晚到结果不得导致已关闭卡片再次弹出或旧词覆盖新词。已经提交的收藏操作不因关闭卡片而假定已撤销。

## 4. 单词收藏业务规则（核心变更）

### 4.1 概念与数据关系

| 概念 | 定义 | 本轮 |
| --- | --- | --- |
| 收藏单词 FavoriteWord | 用户主动保存的一个词典原型，拥有词典引用、基本释义及音标等 | 实现 |
| 附属例句 WordExample | 用户首次收藏单词时遇到的真实原文片段，属于该单词的学习资料 | 实现，允许兼容已有多条例句 |
| 独立句子收藏 FavoriteSentence | 用户主动收藏整个句子的独立资源，未来可有翻译、语法或复习能力 | 不实现；保留领域设计和未来接口边界 |

一个用户的同一 lemmaKey 仍只允许一个活动收藏主体，不按词性、词义、词形、来源书籍拆成多个收藏。附属例句不能单独计为已收藏句子、不能出现在独立句子列表、不能被未来的句子复习直接当成独立句子资源。

关系为 FavoriteWord 1 : 0..N WordExample；正常通过阅读卡片首次收藏时保存当前一条经校验的原文例句；历史数据允许多条，兼容异常缺失时可为零，不能制造例句。当前版本没有主动追加入口。

### 4.2 CR6-F01 两态收藏和操作语义

旧状态 NONE / WORD / CONTEXT 以当前语境是否已保存为依据。新的用户可见状态仅为“收藏”（未收藏）、“已收藏”（已收藏），以单词主体是否存在为依据，与当前句子是否相同无关。

| 当前状态 | 用户动作 | 成功后的状态及结果 |
| --- | --- | --- |
| 未收藏 | 点击收藏 | 已收藏；建立单词主体及当前一条附属原文例句 |
| 已收藏 | 再次点击收藏按钮 | 未收藏；直接删除该单词主体及其附属例句，无二次确认 |
| 已收藏，其他书/章节/句子再次遇到 | 打开查词卡片 | 显示已收藏；不修改记录，不自动追加例句 |
| 已收藏，其他语境再次点击 | 点击已收藏按钮 | 取消整个单词收藏，而非追加本句 |
| 取消后重新收藏 | 点击收藏 | 建立新的收藏主体，并保存本次所在原句，不恢复此前已取消的例句 |
| 请求进行中 | 快速重复点击 | 防止重复提交及乱序覆盖；不得重复创建主体或例句 |
| 请求明确失败 | 收藏或取消失败 | 保留/恢复上一次确认状态，给出可重试错误 |
| 请求结果未知（如已提交后丢响应） | 查询/重试 | 依据真实服务器状态和幂等机制对账，不能静默假成功 |

点击应立即给予视觉反馈，可采用乐观更新或明确的待确认态；明确失败须纠正反馈，未知结果不能当作成功或失败。收藏和取消均无需二次确认；删除后关联的附属例句随主体删除，未来独立句子收藏不应受影响。仅移除成功提示“已保存单词与原文语境”等重复文字，不移除必要的请求错误、加载和不可用提示；收藏成功不额外弹窗或打断阅读。

收藏列表中的取消收藏操作建议与查词卡片保持一致（单击取消、不二次确认、失败恢复），属于本 CR 的默认交互一致性规则。

### 4.3 CR6-F02 附属例句

- 只有用户首次主动收藏单词时，才保存当前经现有原文来源校验的句子及其被点击词面。
- 不因查词、浏览详情、打开书籍或遇到同一单词自动添加任何例句。
- 例句应包含原文句子、原文词面、句内目标词偏移（用于展示高亮）和来源书名快照。书名真实、原书删除后仍可显示；不展示章节名称、语境数量、原文跳转入口。
- 例句使用原文，不从词典、模型或其他书籍生成替代文本，不额外请求翻译。历史已有合法译文可作为保留数据，不要求本轮展示或新增翻译能力。
- 同一单词有多个历史例句时全部保留并可在详情回看，不因新规则自动裁剪为一条。只有用户主动取消整个收藏时才删除其附属例句。
- 当前独立“句子”收藏标签、句子列表、“收藏本句”及语境计数入口取消；不能通过隐藏标签但继续执行旧 append 语义来实现。未来主动追加例句、独立句子收藏应单独批准需求与设计，不保留可触发旧语义的公开入口。
- 对 NOT_FOUND、UNSUPPORTED_QUERY、查询异常等状态继续遵循原有真实词条收藏约束；已收藏主体可按可靠身份确认后取消，不允许将任意未知词伪造为词典条目收藏。详细技术设计明确无 lookupId 场景的安全行为。

## 5. 取消收藏原文定位及历史数据清理

### 5.1 CR6-F03 功能边界

明确取消收藏例句的“回原文”功能。新旧收藏均不再提供跳转到原书、章节或精确原文位置的能力。书名只是静态来源文字。

不再为了收藏跳转而持久化新记录的 EPUB CFI、artifact/章节/块位置、句子在原书中的偏移、定位 quote、原书/章节关联等定位信息。历史已有定位信息也必须清理，而非只隐藏链接。历史语境定位所需的关联字段、索引、定位派生数据及回执载荷是否仍被其他能力使用，需在技术设计逐项盘点并安全迁移；保留字段必须有非定位用途的明确依据。

**必须保留：**
- 用户与单词归属、lemmaKey 唯一性、词条引用、音标、释义和创建时间（内部排序/分页用）。
- 旧的全部原文例句、目标词面、句内高亮偏移及书名快照；不得因相同句子曾出现在不同位置就误删历史例句。
- 保障操作幂等及防止删除后旧回执复活收藏的必要信息。
- EPUB 文本索引、查词时来源真实性校验、书籍阅读进度 CFI/quote、阅读器一般定位与普通“返回阅读”导航。上述与收藏例句跳转不是同一数据生命周期。

说明：句内 wordStart/wordEnd 只用于显示例句高亮，不属于应删除的原书定位数据；书名来源快照也不属于定位信息。若为内部来源筛选保留非定位标识，不得可用于恢复原书章节位置，并须说明必要性。未获额外确认不得删除其他功能的书籍/章节/进度数据。

### 5.2 迁移要求

- 用户已经确认产品层面清理历史定位数据，**不等于授权本轮直接执行数据库删除或迁移**。
- 技术设计须明确现有 V9 表及回执、旧 API 与代码的映射，提出新的向前迁移、备份、测试库演练、数量/完整性核对、恢复方案及正式执行条件。不得修改已应用的 V9 迁移文件。
- 迁移前后核对收藏主体数、各用户归属、历史例句数、例句文本/词面/句内偏移/书名完整性、旧定位字段清理结果；避免跨用户数据丢失或旧客户端重新写入定位。
- 旧收藏跳转 URL 不再触发收藏原文定位；可按普通阅读路径处理或给出明确说明，不能绕过正常授权。普通阅读进度恢复保持。
- 历史快照保留、数据清理与应用代码部署应具备兼容及回退安排。开发/真实数据库执行时间与范围另行确认；文档不得宣称迁移已完成。

## 6. 收藏页面

### 6.1 CR6-L01 紧凑单词列表

当前收藏页呈三段式条目（词、释义、时间/语境数/操作），新版本改为紧凑词汇列表。页面继续使用 UX-U03 正式中性视觉、现有主导航和真实账号数据。

每条列表必须展示：
- 原型单词（lemma），不使用变形词面作为独立收藏标题。
- 真实音标，缺失时不编造。
- 前两至三组词典释义，按第 3 节的真实分组规则。实施默认：桌面最多三组、窄屏或紧凑布局最多两组；实际不足则全部展示。可合理换行/截断过长文本，但不得将同一组拆成独立伪释义；详情可看完整内容。
- 独立发音按钮，点击可播放真实可用的录音。
- 可打开详情的明确交互区域，以及取消收藏操作。

不展示：收藏时间、x 条语境、独立句子标签、原文跳转。页面统计如保留只显示单词总数，不再展示语境总数。保留搜索、排序、分页和必要的错误/加载/空状态；默认搜索单词。建议保留已有按书名筛选能力（以附属例句的书名来源为依据，无需原文定位）；具体查询兼容及缺失来源处理由技术设计落实。取消显示时间不等于取消按创建时间排序。

视觉要求：
- 优先单行或双行紧凑排布，单词、音标、简要释义与操作保持清晰层级；取消多段大留白与每条冗余底栏。短内容桌面行高建议约 64–80px，不以固定高度裁切长释义。
- 使用分隔线或轻量列表容器，避免过重卡片堆叠；响应窄屏，保证字号、按钮命中区域、键盘焦点和可访问名称。
- 点击播放/取消按钮不得误打开详情，点击详情不得误触取消。没有录音或加载失败须有明确反馈。
- 本次不要求重新制作独立原型；实际视觉基于 readict-app 正式页面修改、预览和人工确认，截图归档设计仓库。

### 6.2 CR6-L02 单词详情

点击词条进入详情（优先沿用现有弹窗）：
1. 标题为原型单词、可用音标、真实发音入口。
2. 展示所选词条完整释义组，复用查词卡片的分组规则；不将单个首次释义快照当成全部释义。词典不可用、旧引用失效时展示已保存真实快照并明确提示完整释义暂不可用。不得跨候选误合并或生成假词义。
3. 展示该单词的附属原文例句，目标词面在原句中高亮，书名作为静态文字。无例句时显示真实空状态。历史多条例句仍可浏览。
4. 不显示原文跳转、章节定位、独立句子收藏或主动添加例句按钮。本轮不引入语法分析、翻译、复习、词典额外例句。

完整释义的数据获取方式（按词典引用查询、必要快照或缓存）由后续技术设计决定；须遵守词典数据集授权及快照策略。用户确认的是展示能力，而不是授权保存全部词典内容或重建词典库。

### 6.3 真实发音规则

- 复用已实现的本地真实录音资源和播放器，不使用浏览器 TTS 或模拟录音替代。
- 默认优先已有用户口音偏好对应的可用录音；仅其他口音可用时明确实际口音；无录音或音频未配置时显示不可用。
- 点击才查询/播放，避免页面加载时自动下载或播放全部录音。列表与详情共享播放协调，同一时间最多播放一个词；切词、关闭当前详情、离开页面/退出账号停止旧播放。
- 收藏记录存在不保证当前音频数据集仍可播放；音频缺失、数据集变化、网络错误不影响收藏和释义展示。
- 新增音频查询契约、权限和缓存策略属于技术设计，不在本 CR 预定 URL 或数据表结构；以实际 AudioCatalog 与现有音频端点复用为优先。

## 10. 决策记录及待技术设计事项

### 10.1 已确认的产品决策

| 决策 | 结论 |
| --- | --- |
| 收藏内容 | 首次收藏原句作为单词附属例句，不形成独立句子收藏 |
| 追加 | 不自动追加，未来单独设计主动添加例句 |
| 列表释义 | 前两至三组 |
| 原文来源 | 保留书名，不保留跳转 |
| 历史定位 | 清理历史收藏专用定位数据 |
| 认证 | 登录、注册、找回密码均默认手机号且在第一位 |

### 10.2 为落地而补充的默认规则（可在实施设计评审调整）

保留历史全部例句；取消收藏删除其附属例句、重新收藏保存当次原句；收藏列表也不二次确认；桌面最多三组、窄屏最多两组；保留原书名筛选、内部时间排序、普通返回阅读；仅大小写差异不重复展示词形；保留 X 作为辅助关闭；优先既有口音偏好，详情优先沿用弹窗。这些是根据用户已确认范围推导的执行默认，不是额外声称用户逐项明确选择；如存在冲突，需在详细设计中提出而非擅自扩大功能。

### 10.3 下一步必须完成的技术设计

- 核验实际 COL 数据与原生分组粒度，确定前后端 DTO、分组顺序和数据兼容。
- 两态收藏、首次例句保存、旧 append 禁用、已收藏识别、请求幂等及错误对账的完整 API/事务设计。
- 逐字段列出历史定位清理、保留内容和回执兼容，设计向前迁移、备份、回退、验证及执行批准流程。
- 收藏列表/详情完整释义和录音查询，授权、版本和降级策略；确定紧凑列表与浮层交互实现。
